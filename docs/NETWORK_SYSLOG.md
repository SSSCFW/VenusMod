# Syslog集中ログ収集

Minecraft1.21.1 / NeoForge。既存の [ネットワーク仕様](NETWORK_SYSTEM_SPEC.md) のSyslog収集を追加します。現実のUDPソケット・OSログ・外部Webへは接続しません。既存のネットワークサーバーを使い、新しいブロック・テクスチャ・レシピは追加しません。

## 基本の接続

```text
Router/L2SW/PC ─ 独立したケーブル区間 ─ L2SW ─ Server
送信元IP 192.168.1.10/24                    192.168.1.20/24
```

T字分岐ではなくスイッチの別ポートに配線します。L2スイッチ等も、送信用の管理IPv4を設定してください。ルーターの送信元IPは宛先への経路の出力ポートから選びます。

受信するServer側:

```text
ip 192.168.1.20/24
syslog server on
syslog allow 192.168.1.0/24
```

送信機器側:

```text
syslog target 192.168.1.20
syslog on
syslog test 3 test-message
```

通常の`log`に新しく記録された通信診断・転送・OSPF/BGP/STP/VRRP状態変化などを配送します。以前のローカル履歴をまとめて遡って送る機能ではありません。既存ログの既定severityはinformational(6)です。すべての日本語メッセージから重大度を自動推定する方式ではありません。

## 見る・止める・消す

```text
syslog status
syslog logs
syslog logs 20
syslog clear
syslog off
syslog server off
syslog target none
syslog help
```

サーバーGUI上部の「ログ」ボタンからも収集済みログを開けます。サーバー以外の「ログ」ボタンは従来の自機ログです。新しい履歴を見るには再度ボタンまたはコマンドを実行してください。表示は新しい順、既定12件、最大20件です。

発生tick、受信tick、元の機器名、受信時の送信元IP、重大度、本文を表示します。tickは通信エンジン稼働中の相対時刻で、現実の日時やNTP時刻ではありません。NATで見えるIPが変わっても、元の機器名は別フィールドで残ります。名前は暗号学的な身元証明ではありません。

`syslog off`は送信停止、`syslog server off`は受信停止。`syslog clear`は**自機の受信履歴だけ**を消し、他の機器や従来のローカルログを消しません。宛先・送信設定の変更は古い配送待ちを破棄します。設定編集だけで正常な転送やNAT表をリセットしません。

## 重大度・フィルター

`syslog level 6`で重大度0〜6を配送し、7を除外します。数字が小さいほど重大です。0=emergency、1=alert、2=critical、3=error、4=warning、5=notice、6=informational、7=debug。通常のプロトコルログを集める場合は既定の6を使用してください。

`syslog test 3 MESSAGE`は、重大度3の試験メッセージをローカルに記録します。コマンドの成功は遠隔配送の成功通知ではありません。送信ON・宛先設定・重大度条件・配線が別途必要です。本文は最大200文字で、改行・色指定・制御文字は除きます。

受信側の`syslog allow CIDR`は、**NAT変換後に観測される送信元IP**で範囲を限定します。`syslog allow any`なら到達可能な送信元を許可します。受信サービスは初期OFFですが、ONにした時の既定許可範囲はanyです。重要な収集サーバーでは必要なCIDRとルーターACLを設定してください。

## UDP・ACL・NAT・故障

SyslogはUDP514の**片方向**通信です。L2/VLAN、ルーティング、出力/入力ACLと最終ポートを確認しますが、ICMP pingや返信経路を配送の条件にしません。受信者が送信元LANへの経路を持たなくても、行きの経路だけで到着できます。

NAPT、二段階のルーティング、既存ポート転送も使えます。例えば`syslog target 203.0.113.1 5514`は公開UDP5514へ送信し、ルーターで内部ServerのUDP514へ転送します。内部の515番などへ誤転送した場合は受信せず、NATの新規変換を確定しません。受信サービス停止や受信元フィルター拒否でも変換を確定しません。

`syslog status`に出る到着/破棄数は**シミュレーターの診断値**であり、UDPにACKを追加した意味ではありません。失敗したログを再送しません。配送のたびに成功ログを出すこともなく、配送失敗によるローカル診断は再びSyslogへ流さないので、失敗が再帰的に増殖しません。受信履歴は再転送せず、相互に宛先を指定してもリレーしません。

**完全停止した機器自身は、停止中の故障ログを送れません。** 周囲のルーターやスイッチにも送信を設定し、隣接喪失や経路切替のログを集めてください。途中の断線、ACL拒否、受信サーバーの停止はゲーム内の配送失敗になります。復旧後に過去の失敗ログを再送する機能や、死活監視の自動ポーリングはありません。

## マルチプレイ・保存

送信設定・受信設定・履歴閲覧・消去は既存の機器メニューの所有者/共有権限に従います。`public on`でWeb等を公開しても、収集ログや設定画面を公開しません。ネットワークからのログ受信と、プレイヤーが履歴を閲覧する権限は別です。ログ本文に秘密情報を記録しないでください。

保存形式はv9。送信ON/OFF、宛先IPv4/UDPポート、severity閾値、受信ON/OFF、受信元CIDRを、設定・装着品・故障・所有権と一緒に機器アイテムへ保存します。v1〜v8も読み込め、以前の機器では送受信ともOFFから始めます。古いMODへのダウングレード互換性は保証しません。

**収集済み履歴・配送待ち・統計はランタイムのみです。** 受信機器の回収/アンロード、ワールド停止・サーバー再起動で失われます。送信元が撤去されても、すでに到着した履歴は収集機器が稼働中なら残ります。永続的な監査・バックアップ用サービスを実装した意味ではありません。

## 軽量化と範囲

配送待ちは全体1024件、1送信元32件。新規受付は送信元ごとに20tick当たり16件まで、配送は1tick当たり2件までです。送信元をラウンドロビンで処理し、大量出力する1台だけが他の待ちを独占しないようにしています。200tick以上待ったログは破棄し、長時間分の処理を1tickへ集中させません。

受信履歴は1台256件、全体4096件で古いものから削除します。通常の通信量・キュー・最大経路長の上限も適用します。大量の実パケット列や文字列を作らず、既存ケーブルにTickerを追加しません。ログ用の小さな制御データは経路メタデータとして評価し、大容量転送のような帯域予約や厳密なUDP遅延・損失乱数は追加していません。

GUI/JEIの共通ガイドは18トピック72手順。既存の4/16幅ケーブル8種、74PNG、全モデルとレシピはそのままです。新規の外部依存やネットワークPayloadは不要です。

参考: RFC5424の重大度、RFC5426のUDP514・無応答方式。IPv4・メタデータのゲーム用モデルであり、完全なRFCワイヤ形式、facility/structured-data、IPv6、DNS名の宛先、TCP/TLS、再送、暗号化、永続保存は未対応です。
