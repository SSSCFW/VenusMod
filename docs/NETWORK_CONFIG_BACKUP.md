# 機器設定のバックアップと確認付き復元

既存ネットワーク機器の設定を手元に保存し、設定ミスの前へ戻す機能です。Serverへの遠隔保管もできます。実ブラウザー・OSファイル・外部TCP接続は使用しません。ワールド全体、アイテム収納、機器の装着品をバックアップする機能ではありません。

## まず手元に保存する

機器の設定GUIのコンソールで、変更前に実行します。

```text
backup save before
backup list
```

保存名は英数字・`_`・`-`の1〜24文字です。同じ名前は上書きしません。別名で保存するか、不要になった控えを`backup delete before`で明示的に削除してください。満杯になっても古い控えは自動削除しません。

## 確認して復元する

```text
backup restore before
```

機器名、機種、代表IP、静的経路の件数、復元の注意事項を表示します。まだ適用しません。表示された8桁のトークンを使い、同じ機器画面で30秒(600サーバーtick)以内に実行します。

```text
backup confirm 表示されたトークン
```

確認は一回限りです。確認中に対象の設定・装着モジュールの能力・保存内容が変わっていれば、古い値から上書きせず拒否します。画面を閉じた場合もやり直してください。同じ機種にしか復元できません。IP、VLAN、経路等の変更で通信できなくなっていても、手元の控えは配線を経由せず復元できます。登録機器数上限を超えて通信エンジンに未登録の機器はこの版のメニュー操作対象外です。

復元は入力欄1個ではなく**保存時のネットワーク設定全体**です。IP、Router IDも戻るので、別の機器と重複しないことを確認してください。別の同型機器に控えを取得して復元することもできますが、機器ID・所有権は複製しません。変更がある場合は影響する物理ネットワークの通信を再確立します。同じ設定の復元なら転送・制御期限をリセットしません。

## 巻き戻さないもの

故障、装着アイテム、本体性能、WANモジュール、所有者・共有者、現在のサービス公開設定、実レッドストーン出力、通信中の状態は復元しません。控えだけで修理・アイテム複製・故障率改善・所有権取得はできません。新しく高い固定速度や光設定に戻す場合、必要なモジュールがなければ拒否します。

過去のDHCP配布予約は保存しません。現在の配布予約は保持し、予約の残るプールと復元プールが違う場合は復元を拒否します。簡易DHCPで現在予約がある場合はLANアドレスの巻戻しも拒否します。明示的に配布状況を整理してから復元してください。既存の予約を黙って解放してIPを再配布することはありません。

安全出力の**方針**は設定として戻りますが、有効期限・継続更新ジョブは戻りません。実際に設定を復元すると、その機器の継続制御は終了します。stop/valueの端末は安全値から新しい命令を待ちます。holdは現在の出力を保持し、控えを取った時の出力値を復活させません。

## サーバーへ保管する

```text
設定元 Router 192.168.1.10 ─ L2SW ─ 保管Server 192.168.1.20
```

各機器にIPと配線を用意し、保管Serverで有効にします。

```text
backup server on
```

設定元で実行します。

```text
backup send 192.168.1.20 router_before
backup list 192.168.1.20
```

`send`はその時点の設定元の現在設定を保存します。手元の既存控えを自動送信する命令ではありません。遠隔保管は初期OFFです。Server以外で受信サービスを有効にすることはできません。停止は`backup server off`で、保存済みの控えは残ります。

**両側の機器の管理・明示共有権限が必要**です。`public on`によるWeb等の公開では、保管庫の一覧・中身・保存操作を許可しません。信頼しているServerへだけ保存してください。そのServerの管理者・共有者は保管した機器設定を取得できます。現実のパスワード・秘密鍵を設定名やデータに書かないでください。

## 取得と復元は別操作

```text
backup fetch 192.168.1.20 router_before recovered
backup restore recovered
```

`fetch`は許可されたサーバーの控えを手元へ保存するだけで、動作中の設定を書き換えません。設定を壊してサーバーへ届かなくなる前に取得しておくか、通信経路を復旧してから取得してください。最終的な復元には前述の確認トークンが必要です。

名前による宛先指定と、NATの公開ポートを指定できます。

```text
backup send vault.local:9001 before
```

実サービスはTCP5001です。ルーターで公開9001→内部5001等のポート転送を設定できます。VLAN・往復経路・ACL・NATの変換後ポート・Server種別・受信ON・権限・保存容量を検査し、失敗時は控えを書き込まず、新規NAT変換の確定や既存変換の延長もしません。名前解決が別に必要な場合、その正常なDNS通信のキャッシュ/履歴とは区別します。

小さい設定データは既存の同期的なメタデータ往復検査で扱います。**大容量転送フローの開始や帯域予約、転送完了待ち、実TCPワイヤ形式は追加していません。** 通信ボトルネックを無視して大容量ファイルを瞬時に転送する機能ではなく、容量制限付きの設定控えです。

## 持ち運び・保存・破損保護

保管庫と遠隔受信ON/OFFを、機器のBlockEntityに別のバージョン付きデータとして保存します。機器を通常採掘すると、控えも設定・装着品・故障・所有権とともに1個の機器アイテムへ入り、再起動/再設置後も残ります。Profile保存形式はv12のままで、保管庫のない旧機器は空の保管庫・受信OFFで読み込みます。ワールドの更新前バックアップは残してください。

控えに保管庫そのものは含めないので、バックアップを重ねても再帰的に巨大化しません。確認トークンや編集中の状態も保存しません。チェックサムは破損検出用で、暗号化や署名ではありません。通常のゲーム内権限に加え、ワールドファイルやアイテムデータを編集できる管理者から内容を隠す機能はありません。

破損/未対応の保管庫は、普通の機器設定を壊さず、原データを隔離して保存し直します。控えの操作はエラーとなり、黙って空に初期化しません。原データを修復せず捨てると決めた場合だけ、管理者・共有者が次を使います。

```text
backup discard-corrupt confirm
```

この操作は破損した保管庫だけを明示的に破棄します。正常な控えは`backup delete`を使います。

## 軽量化と範囲

1台8件、設定文字列合計64KiB、1件は既存Profile上限32KiB。新規保存は1ディメンションのロード済み保管合計4MiBでも制限します。保存済みの控えをロードした結果が全体上限を超えても、既存の控えを捨てず新規保存を停止します。これは全ワールドの保存容量やTPSを保証する数値ではありません。

受付は既存メニューのプレイヤー/ディメンション要求予算を共用し、期限の常時Tickerや無制限の保留処理は追加しません。全体容量は保管命令時のみロード済み機器を1回走査して集計します。保管庫を通常のフォーム周期同期や公開Web画面へ送信しません。

GUI/JEI共通ガイドには既存テクスチャの機器アイコンを使った5手順を追加しました。136種カラーケーブルの4/16幅、画像、モデル、レシピ、ゴーグル、専用タブは変更しません。操作は現在コンソールと共通ガイドで、保管庫専用のフォームは今回の範囲外です。
