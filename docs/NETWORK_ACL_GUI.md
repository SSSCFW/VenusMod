# ACLの設定GUI

ルーター/L3スイッチの通常コンソール左下「ACL設定」から、通信の許可・拒否ルールを追加・確認・削除できます。JEIは不要です。PCなど経路転送機能を持たない機器では編集できません。

## 入力と追加

| 項目 | 入力内容 |
| --- | --- |
| 機器ポート | P0北・P1東・P2南・P3西・P4上・P5下。実際に配線した面を選びます |
| 方向 | inは受信、outは送信 |
| 順序番号 | 1〜65535。小さい番号から評価し、最初の一致で決定 |
| 動作 | 許可（permit）または拒否（deny） |
| プロトコル | IP・ICMP・TCP・UDP・OSPF・VRRP。IPはすべてのIP通信 |
| 送信元・宛先 | IPv4、CIDR、any。単一IPv4は/32、anyは0.0.0.0/0 |
| 宛先ポート | TCP/UDPでは0〜65535またはany。それ以外はany |

入力後に「規則を追加」を押します。CIDRのホスト部は正規化され、例えば `10.20.0.42/24` は `10.20.0.0/24` として保存します。同じポート・方向・順序番号のルールは上書きせず拒否します。上限は機器全体で64規則です。

**規則が一つでもあるポート方向は、どれにも一致しない通信を暗黙に拒否します。** TCP80だけ許可すると、その方向ではICMPやDNSも通らなくなります。返信も別に評価するため、往路を許可するだけでは疎通を保証しません。設定のないポート方向は全許可です。

## 一覧と確認付き削除

「ACL一覧」で現在の規則を手動表示します。結果欄はCLIと共通の最後のサーバー表示で、新しい応答が届くまでは前回の結果も含みます。ホイールでスクロールできます。画面を開いたり入力しただけでは一覧要求や設定変更を送りません。

削除時は一覧を参照して**削除するルールの全条件**を入力し、「個別削除」を押します。この時点では未送信で、正規化した全内容を表示します。「削除を確定」で初めて要求を送り、サーバーがポート・方向・順序番号・許可/拒否・プロトコル・送信元・宛先・宛先ポートの一致を検査します。同じ番号の規則が別内容へ置換されていれば拒否します。

「確認を中止」、入力や選択肢の変更、ガイド/画面移動、リサイズで削除確認を取り消します。下書きは同じGUI内で保持しますが、GUIを閉じた後や再接続後には保存しません。確認は一回限りです。**そのポート方向の最後の規則を削除すると、全許可へ戻ります。**

GUIでは規則の全消去を行いません。既存CLIの番号指定削除・方向別clearは引き続き使用できます。

```text
acl add 0 in 10 permit tcp 10.20.0.0/24 any 80
acl
acl delete-match 0 in 10 permit tcp 10.20.0.0/24 any 80
```

`delete-match` はGUIと同じ内容一致削除です。従来の `acl delete 0 in 10` は番号による削除であり、内容の一致検査はしません。

## 権限・通信・保存

既存Command Payloadを使用し、サーバー側で所有者/共有権限、開いているメニュー、距離、生存/観戦状態、入力長、要求数を確認します。通信のACLと機器管理権限は別です。ACLの誤設定で通信を遮断しても、所有者は機器を直接右クリックして修正できます。

未存在や内容不一致による削除拒否、重複追加、誤入力、空の方向のclearでは、設定・転送・NAT変換表を再初期化しません。実際にルールを変更した場合は、従来どおり影響する物理網の通信を再確立します。

機器保存v16、通信network-3、既存の136種ケーブル、4/16幅、画像・モデル・レシピを維持します。ACLは従来の機器保存と採掘/再設置に含まれ、装着品・故障状態・所有権の保持方法を変更しません。サーバー/クライアントともこの機能を含む同じMODを使用してください。

共通ガイドのACLページとJEIに、入力・暗黙deny・返信・確認取消・最後の規則の削除の説明を追加しています。23トピック97手順を維持し、長い説明はJEIの続きカードへ分割します。外部ネットワーク、OSのソケット、シェルには接続しません。

実施した検証と未実施の範囲は [検証記録](NETWORK_ACL_GUI_VERIFICATION.md) を参照してください。
