> ACLをフォームで操作する場合は [ACL設定GUI](NETWORK_ACL_GUI.md) を参照してください。後続実装の現行対応範囲はREADMEと各機能の文書に記載しています。

2026-10-17の追加実装。対象はMinecraft 1.21.1 / NeoForge 21.1.x、作業ブランチは `feature/venus-hostile-mobs`。Create非依存、JEI任意です。全体計画は [仕様書](NETWORK_SYSTEM_SPEC.md)、初期配線・機器の基本は [使い方](NETWORK_IMPLEMENTATION.md) を参照してください。

**初期版に残っていたACL・DHCPリレー・JEI独自ガイドカテゴリを今回追加しました。** 以前の文書にある「未対応」のうち、この3項目は本書の範囲で対応済みです。OSPF/BGP/IPv6等まで完成したという意味ではありません。

## 1. 追加した機能と維持したもの

ルーター/L3スイッチにIPv4 ACL、DHCPリレーを追加。DHCPサーバー/ルーターには複数の配布プールと、再読込しても残る配布予約を追加しました。機器GUIのガイドは接続図付きの大きな画面に変更し、同じ説明をJEIの「ネットワーク接続ガイド」カテゴリで表示します。

ケーブル8種類の**芯・接続腕・衝突形状は4/16幅のまま**です。既存の74 PNGとモデル生成処理は変更していません。ガイドの図も登録済みのテクスチャ付き機器/ケーブル/モジュールアイコンを使います。

全通信はJava内の仮想ネットワークです。Web・DNS・DHCPを追加しても、現実のブラウザー、OSソケット、外部HTTP、JavaScriptを使いません。

## 2. IPv4 ACL

### 設定形式

```text
acl
acl add PORT in|out SEQ permit|deny ip|icmp|tcp|udp SRC DST [DST-PORT]
acl delete PORT in|out SEQ
acl clear PORT in|out
```

`PORT` は機器の面番号（0北・1東・2南・3西・4上・5下）。`SEQ` は1〜65535で、**小さい番号を先に検査し、最初の一致で許可/拒否を決定**します。`SRC` と `DST` は `10.0.1.0/24`、単一IPv4、または `any`。最後の宛先ポートはTCP/UDPのみ指定でき、省略/`any` なら全ポートです。

`in` はその面から受信するとき、`out` は送信するときです。設定のない方向は未適用で全通信を許可します。1件以上の規則を設定した方向は、**どの規則にも一致しなければ暗黙のdeny**になります。`clear` はそのポート・方向のACL適用を外します。GUIの管理権限はこのACLとは別なので、設定を誤っても所有者は機器を直接右クリックして修正できます。

### 例: PCからのWebだけ許可

```text
acl add 0 in 10 permit tcp 10.0.1.0/24 any 80
```

この方向ではTCP宛先80番だけを通し、未一致のICMP/DNS/その他のTCPを拒否します。許可した通信でも、相手側の経路や返り側のACLが不適切なら失敗します。

### 例: pingだけ拒否し、ほかは許可

```text
acl add 0 in 10 deny icmp any any
acl add 0 in 20 permit ip any any
```

`acl` で設定を表示します。拒否時の診断には機器名、ポート、方向、規則番号（または暗黙のdeny）を表示します。1機器の上限は64規則。同じポート・方向・番号の重複追加は拒否し、既存規則を黙って上書きしません。

### サービスごとの検査

| 操作 | 仮想プロトコル/宛先ポート |
| --- | --- |
| ping / trace | ICMP |
| DNS | UDP 53 |
| open | TCP 80 |
| transfer | TCP 5000（ゲーム用） |
| redstone | TCP 25570（ゲーム用） |
| DHCP relay–server | UDP 67 → 67 |
| DHCP client–relay | UDP 68 → 67、返りは67 → 68 |

Web/DNS/仮想転送を `ping` の成功で代用しなくなったため、ICMPだけを拒否しても他サービスを別に許可できます。IP ACLはARPを対象にしません。

**再現範囲:** これはIPv4メタデータに対するステートレスACLです。TCPの完全なハンドシェイク、ステートフルFW、TCPフラグ、送信元ポート条件、IPv6 ACLは未実装。通常の仮想TCP/UDP要求は送信元ポート49152、応答では送受信IP/ポートを反転して検査します。

## 3. DHCPプールとリレー

### 配布プール

```text
dhcp-server on
dhcp-pool add 10.0.1.0/24 10.0.1.100 10.0.1.150 10.0.1.1 10.0.2.10
dhcp-pool
dhcp-pool delete 10.0.1.0/24
dhcp-pool clear
```

追加の引数は順に、サブネット、開始アドレス、終了アドレス、デフォルトゲートウェイ、DNSです。ゲートウェイ/DNSは `none` も指定可能。重複するサブネット、ネットワーク/ブロードキャストアドレス、逆転した範囲、別LANのゲートウェイは拒否します。最大16プール、1プール最大4096候補です。

明示プールが一つもない場合、従来の直結LAN向け簡易プールは残ります。ただし**別LANへのリレー配布には、そのLAN用の明示プールが必須**です。サーバー自身のLANのプールを誤ってクライアントへ配布しません。

### 例: LAN-A → Relay → LAN-BのDHCPサーバー

```text
Client -- LAN-A -- Router/Relay -- LAN-B -- DHCP Server
          10.0.1.0/24              10.0.2.0/24
```

ルーターのクライアント側をP0、サーバー側をP1とした例です。実際には配線した面番号を使ってください。

ルーター:

```text
port 0 ip 10.0.1.1/24
port 1 ip 10.0.2.1/24
dhcp-server off
dhcp-relay 0 10.0.2.10
```

サーバー:

```text
ip 10.0.2.10/24
gateway 10.0.2.1
dhcp-server on
dhcp-pool add 10.0.1.0/24 10.0.1.100 10.0.1.150 10.0.1.1 10.0.2.10
```

クライアント:

```text
dhcp
ping 10.0.2.10
```

リレーはクライアント側IP `10.0.1.1` を `giaddr` 相当の情報として使います。サーバーはこの値でLAN-Aのプールを選びます。中継側のUDP67往復経路、LAN側UDP68への応答、ACLを確認し、ACKが届く条件を満たしたときだけ端末設定と配布予約を確定します。失敗した要求でプールを消費しません。

解除:

```text
dhcp-relay 0 none
```

### 配布予約の保持

```text
dhcp-bindings
dhcp-bindings clear
```

同じ機器IDには、同じプールで利用可能な既存予約を優先します。サーバーの配布予約は設定と一緒に保存されるため、クライアントがアンロードされていても、その予約アドレスを別クライアントへ再配布しません。実際に使われているアドレス、ゲートウェイ、VIPも候補から除外します。

上限はサーバー1台につき128予約。**現段階では手動DHCP要求・期限なし予約であり、リース期間やT1/T2による自動更新は未実装**です。`clear` は管理者による全予約解除です。再使用しない端末を整理する場合に使い、単なるプール枯渇の回避目的で稼働中/復帰予定の端末の予約をむやみに解除しないでください。

## 4. GUIとJEI

機器GUIの「ガイド」で、コンソールの小さな欄ではなく**接続図と手順を表示する画面**を開きます。10トピック（LAN、VLAN、ルーティング、光、WAN、強化、冗長化、ACL、DHCPリレー、設備操作）を前/次で切り替え、本文はホイールでスクロールできます。Escで設定へ戻ります。表示中は背後のインベントリをクリック/ドラッグできないようにしています。

JEIには「ネットワーク接続ガイド」の**独自カテゴリ**を登録します。32手順を1手順1カードで表示し、関連機器から用途を辿れます。GUIとJEIは共通の説明・図を使い、JEIがなくても機器GUIで説明を読めます。CreateのPonderのような3Dアニメーションではなく、テクスチャ付き機器アイコンを用いた静的な接続図です。

## 5. 保存互換・軽量化・検証

設定フォーマットをv2に拡張し、旧v1を読み込めるようにしています。旧機器へACLを勝手に適用しません。新しいACL・リレー先・プール・予約は採掘/再設置の保存に含まれます。新形式を古いMODが読めるという下位互換ではないため、更新前のワールドバックアップは残してください。

既存の通信要求/探索/経路/キュー/VLAN上限を維持し、ACL判定や配布候補の検索も要求全体の予算に加算します。予約やガイドを毎tick全走査する処理は追加していません。GUIガイドの内容は静的でサーバーへ問い合わせません。

ローカルのJava 21で、新規のサービス検査159項目とガイド検査89項目が成功。機能がない状態で失敗を確認してから実装しています。追加のGameTestは実配線経由のリレー/ACL、機器アイテムへの予約保存、旧設定移行、登録済みアイコンを検査します。全体ビルドと既存の形状・74 PNG検査も、変更コミットの `Build 1.21.1 NeoForge` で実行します。

実クライアントでの目視、JEI画面の実操作、シェーダー互換、大規模マルチプレイTPS測定はこの自動検査とは別です。全仕様の完成やすべての描画環境の無不具合は保証していません。

## 6. 残る主な項目

OSPF/BGP/IPv6/NAT/IPsec/LACP、本来のBPDU・VRRP広告タイマー、8/24ポート、PON分岐、ISP契約、惑星間通信、未ロードの配線中継、カメラ映像、物流搬送等は残っています。今回対応したACL・リレーと混同しないようにしてください。
