# NAT/NAPT・ポート転送

Minecraft 1.21.1 / NeoForge。承認済みの [全体仕様](NETWORK_SYSTEM_SPEC.md) のうち、**IPv4 NAPTと、外側インターフェースIPのTCP/UDPポート転送**を追加します。全仕様の完成ではありません。実ソケット・HTTP・ブラウザー・外部LANは使いません。

## 最初の構成

```text
PC 192.168.10.10 ─ L2SW ─ Router P0 inside 192.168.10.1
Web 192.168.10.20 ─┘                  P1 outside 203.0.113.1 ─ Server 203.0.113.20
```

図は論理構成です。各ケーブル区間は独立させ、途中のT字分岐は作らないでください。P0=北、P1=東、P2=南、P3=西、P4=上、P5=下。機器の向きと世界方位は別です。

ルーター:

```text
port 0 ip 192.168.10.1/24
port 1 ip 203.0.113.1/24
nat port 0 inside
nat port 1 outside
nat on
```

PCは `ip 192.168.10.10/24` と `gateway 192.168.10.1`。外側Serverは `ip 203.0.113.20/24`。この直結例ではServerにprivate側への経路は不要です。PCから `ping 203.0.113.20` や `transfer 203.0.113.20 100` を実行すると、ルーターの外側IPと割り当てたポート/照会IDへ変換して往復します。

**NATは経路を作りません。** 遠くのネットワークへ接続する場合は、静的経路または [OSPF](NETWORK_OSPF.md) の経路が別に必要です。NATを有効にしただけでWAN契約の速度制限を回避することもありません。

## ポート転送でLANのWebを公開

LANのWeb機器を192.168.10.20/24、gateway 192.168.10.1、`web on` に設定します。ルーターで:

```text
nat forward add 1 tcp 8080 192.168.10.20 80
```

引数は、外側の機器ポート、TCP/UDP、公開ポート、内部IP、内部ポートです。外側のPCから:

```text
open 203.0.113.1:8080
```

固定のゲーム内Webサービスへ接続します。8080→80の変換後のポートを確認するため、8080→81と誤設定してもWebが開いたことにはしません。`redstone IP:PORT 15` と `transfer IP:PORT 100` にも対応します。実際の内部サービスのポートはWeb=80、レッドストーン=25570、仮想転送=5000です。

サービスを使うプレイヤーには、**対象の内部機器の所有権/共有権限**が必要です。所有者が `trust プレイヤー名` で共有するか、対象サービスを `public on` にして公開してください。NATの公開規則は機器の管理権限を与えません。相手のIPが変換されてもプレイヤーの権限判定は省略しません。

`ping`で外側IPを指定した場合はNATルーター自身への照会です。ICMPのpingだけではTCPポート転送の動作確認になりません。

## 表示・解除

```text
nat
nat sessions
nat forward delete 1 tcp 8080
nat overload off
nat clear
nat off
nat help
```

`nat overload off` は新しい外向き動的NAPTを止め、設定済みのポート転送とその返信は維持する設定です。`nat clear` は設定を消さず、変換表と稼働中の仮想転送をリセットします。

機器・配線・ACLなどの構成変更では既存のキャッシュ失効に合わせて変換表を破棄します。現段階の失効はディメンション単位で、無関係なネットワークの転送にも影響し得ます。局所再計算は引き続き改善対象です。

## ACLの順序

このゲーム内実装では、入力ACL → 宛先変換 → 経路選択 → 送信元変換 → 出力ACLの順です。

- 外向き通信: 内側の入力ACLはprivateの送信元IP、外側の出力ACLは変換後の外側IPを見ます。
- ポート転送: 外側の入力ACLは公開8080番、内側の出力ACLは内部80番を見ます。
- 返信: 返信方向も同様に、実際に各リンク上に流れるIP/ポートを検査します。

[ACLの規則](NETWORK_SERVICES_GUIDE.md) はNATとは別です。NATに一致しない別宛先への通常ルーティングまで自動的に遮断するファイアウォールではありません。外側インターフェース自身宛ての未公開TCP/UDPは、変換先がないとして拒否します。

往復経路、ACL、宛先機器、実サービスのポートを検査してから変換表を確定します。失敗した要求で新規エントリーを残さず、既存エントリーの期限も延長しません。通信先のIP/ポートまで一致する返信だけを復元します。

## 保存・故障・軽量化

保存形式はv4。v1/v2/v3は読み込め、旧機器のNATはOFFで移行します。NATの内外ポート、有効状態、動的変換の有無、ポート転送規則は、通常採掘で設定・装着モジュール・故障・所有権とともに引き継ぎます。**稼働中の変換表は保存せず再作成**します。古いMODへ戻す前提の互換性はないため、更新前のワールドバックアップを保持してください。

変換表は1機器128件、同じinsideポート/内部IPは32件、1ディメンション全体で2048件、1要求で16変換まで。ポート転送は32規則までです。上限で勝手に他の通信を上書きせず、明示的な失敗を返します。

アイドル期限はTCP120秒、UDP30秒、仮想ICMP照会10秒です。ゲームのサーバーtickで進みます。継続転送中だけ期限を延長し、期限イベントはエントリー1件につき1件のまま更新します。期限切れの回収は1tick最大64件、回収待ちでも期限切れエントリーで受信を許可しません。現段階は実TCPハンドシェイクやFIN/再送状態ではなく、メタデータと仮想転送のモデルです。

2段のNAT、2段のポート転送、異なるLANで同じprivate IPを使用する2拠点、OSPFで学習した外向き経路を検査対象に含めています。重複private IPは別のL2区間に分離されている必要があります。

ケーブル8種類の4/16幅・独自テクスチャ74枚・ブロックモデル・レシピは変更していません。GUI/JEIに同じテクスチャ付き機器アイコンを用いたNATガイドを追加し、合計12トピック41手順になります。

## 再現範囲と未対応

NAT/NAPTのアドレス・通信ポート/ICMP照会ID変換を参考にしています（基礎資料: RFC 3022）。これは実機互換のTCP/IPスタックではありません。hairpin NAT、任意の公開IPを使うBasic NATの1対1マッピング、IPv6 NAT、フラグメント/ICMPエラー内のヘッダー変換、ALG、VRRPのNAT状態同期は未対応です。外側IPは該当ポートの実設定IPを使います。

NATの故障切替で既存接続を無損失に引き継ぐことは保証しません。BGP、複数エリアOSPF、本来のSTP/VRRP、8/24ポート筐体、PON分岐、惑星間通信などの残項目は従来どおり未完成です。

検証結果は [NETWORK_NAT_VERIFICATION.md](NETWORK_NAT_VERIFICATION.md) に記録します。コード検査・GameTest・実クライアント目視を区別します。
