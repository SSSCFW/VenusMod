### 実際の入力と通信

隔離した一時ワールドへPCとサーバー、青色Cat5eケーブルを配置し、サーバーから正規の機器メニューを開いています。別JVMのRobotから同じXvfb画面へクリック・英数キーを送り、GUIのハンドラーを直接呼ばずに操作しました。

- 不正な宛先は「未送信」となり、前回のサーバー表示を変更しない。
- Ping、経路確認、名前解決が実際の配線と既存のCommand Payloadを通って応答する。
- 転送量が誤入力でもPingを実行でき、high指定の仮想転送と通常サーバーtickによる進捗を確認する。
- 不正な転送量では2本目の転送を作らず、一覧で優先度・最終割当帯域を表示する。
- ウィンドウ変更とガイド往復で診断の下書きを保持し、CLIの未送信テキストも保持する。
- 診断画面の背後にあるJEI入口やスロットへ入力を渡さない。
- 通常ケーブルを壊した後の診断は成功を返さず、設定・装着品・Inventoryを勝手に変更しない。

`PASS.txt`、`interaction-PASS.txt`、`diagnostics-PASS.txt` のすべてを確認しました。`10-diagnostics-invalid.png` は未送信エラー、`11-diagnostics-transfer.png` はhigh優先度と最終割当1.00Gb/s、`12-diagnostics-disconnected.png` は断線後の到達不能表示です。日本語、結果欄と操作ボタンの分離、リサイズ後の配置を画像で確認しました。結果欄は最後のサーバー表示であり、送信要求それ自体を成功扱いしない既存仕様を維持しています。
