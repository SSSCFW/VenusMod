# ポート単位故障 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. 承認済みネットワーク仕様の故障・修理を継続実装する。

**Goal:** 機器全停止と独立したポート故障を導入し、残ったポートと冗長化を使って運用できるようにする。
**Architecture:** Port.failedを物理故障としてProfile v15の末尾へ保存する。リンク成立/VLAN通過は共通の稼働判定を使い、故障イベントは既存1200tick予約の中で種類を選ぶ。設定復元で物理状態は巻き戻さない。
**Tech Stack:** Java21、Minecraft1.21.1、NeoForge21.1.x。追加依存なし。
**Spec:** docs/NETWORK_SYSTEM_SPEC.md §6/§9、元の故障・冗長化要件。

## Global Constraints
- feature/venus-hostile-mobsだけに反映。既存Build 1.21.1 NeoForgeだけを使う。
- 136種・4/16幅ケーブル、既存画像/モデル/レシピを維持。実OS/ネットワークには接続しない。
- 旧v1〜v14はポート故障なしで読み込む。故障・装着品・所有者は持ち運びで保持。
- GUI/CLIを権限・距離・メニュー・入力上限で検証。修理は既存キットを消費。

## Review Focus
- enable、モジュール交換、バックアップ復元で無料修理にならないこと。
- 完全安定化が本体/ポートどちらのランダム故障も厳密に防ぐこと。
- ポート障害を本体故障と誤認して全ポート・レッドストーンを即停止しないこと。
- Shift修理で狙った世界方位の1ポートだけを直し、健康/権限外でキットを減らさないこと。
- 同時GUI編集で最新の物理故障状態を消さず、独立した別物理網の転送を壊さないこと。
