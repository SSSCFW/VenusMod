# Syslog 集中ログ収集 Implementation Plan

> 実行: このセッション内で実装・試験し、既存 feature/venus-hostile-mobs に反映する。

**Goal:** 離れた装置の新しいログを既存ネットワークサーバーへ収集し、故障や経路切替を一か所で確認する。
**Spec:** docs/NETWORK_SYSTEM_SPEC.md (サーバー/Syslog/監視、マルチ権限、軽量化、設定持ち運び)
**Architecture:** 既存のlog入口→制限付き配送キュー→IPv4 UDP片方向NAT/ACL経路→受信者別のリングバッファ。保存v9で設定だけを保持。画面は既存CLIと共通GUI/JEI接続図を使用する。
**Tech Stack:** Java21 / NeoForge21.1.235 / Minecraft1.21.1。Create6.0.10との既存検査を保持。

## Global Constraints

既存ブランチ・既存workflowのみ。4/16幅ケーブルと74PNG/モデル/レシピを変更しない。実ネットワーク/OS/外部ブラウザーへは一切接続しない。上位の包括的な実装・push継続依頼に基づく段階作業。実行していない試験を成功と書かない。

## Review Focus

- UDPの返信不要と、最終サービスポート・NAT変換の確定を分離する。
- 送信失敗が次のSyslogを生成する無限再帰、1台の大量ログによる他機器の飢餓を防ぐ。
- 完全停止した送信元から故障ログが瞬間移動しない。受信サーバー停止・ACL拒否・断線を反映。
- 設定のみの変更で既存転送/NATを消さず、旧保存形式/GUIフォームを壊さない。
- 受信ログ閲覧・消去は管理権限のみ。公開Web経由で非公開収集ログを漏らさない。

## Rulings

数値IPv4と任意の宛先UDPポートに限定し、DNS再帰/問い合わせログの循環を増やさない。受信は既存Serverのみ、初期OFF。ログ本体と配送待ちはランタイムのみで保存しない。既定severityはinformational(6)、明示testは0〜7を選択可。これはRFC5424/5426を参考にしたメタデータ実装で完全なワイヤ形式・TLS・永続監査サーバーではない。
