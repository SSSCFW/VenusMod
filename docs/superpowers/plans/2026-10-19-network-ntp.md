# 仮想NTP時刻同期 Implementation Plan

> REQUIRED SUB-SKILL: superpowers:executing-plans。承認済みのネットワーク仕様を継続実装する。

**Goal:** ゲーム内の機器時計をネットワーク経由で合わせ、Syslogの発生/受信表示に使う。
**Architecture:** 仮想基準サーバー1台とクライアント。UDP123の往復・サービス・NAT取引が成功したときだけ4時刻から補正。表示時計とすべての期限用tickを分離。設定だけ永続化、同期状態と補正値はランタイム。
**Tech Stack:** Java21、Minecraft1.21.1、NeoForge21.1.235。外部依存の追加なし。
**Spec:** docs/NETWORK_SYSTEM_SPEC.md のNTP・監視・軽量化・永続保存要件。

## 制約と判断
- 作業ブランチはfeature/venus-hostile-mobs、workflowは既存build-1.21.1.ymlのみ。
- 136種の4/16幅カラーケーブル、全モデル/テクスチャ/レシピを変更しない。
- 今回はローカル基準サーバーとクライアントだけ。階層中継/複数候補/認証/NTS/実NTPバイト形式は対象外。
- server onはネットワークサーバーのみ。サーバー役とクライアント役の同時有効化は拒否。
- 1機器1宛先、数値IPv4と公開UDPポート。周期1〜3600秒、全体256クライアント、1tick2処理。手動syncも同じ待ち行列へ入れる。
- 手動offset ±86400000ms、drift ±1000ppmは表示時計だけに適用。同期の補正値・状態は回収/再読込で破棄。
- 到達失敗や処理上限は既存時計を維持。最終成功から3周期を越えたらSTALE。障害中はPAUSED表示。再送は次の定期時刻のみ。
