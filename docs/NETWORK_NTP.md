# 仮想NTPと機器時計

Minecraft1.21.1 / NeoForgeのゲーム内ネットワークで、機器の**表示時計**を基準サーバーへ合わせます。実NTPサーバー、OS時計、外部UDPソケットには接続しません。経路やNAT、制御、安全出力のタイマーは従来の単調tickを使い、時計補正の影響を受けません。

## 最初の設定

```text
PC 192.168.1.10/24 ─ L2SW ─ Server 192.168.1.20/24
```

それぞれをスイッチの別ポートへ独立したケーブルで接続し、IPを設定します。基準Server側:

```text
ip 192.168.1.20/24
ntp server on
```

PC側:

```text
ip 192.168.1.10/24
ntp target 192.168.1.20
ntp on
ntp status
```

初期はWAITINGで、次の予約処理で通信を検査してからSYNCEDになります。画面の状態表示・補正値だけでなく、T1〜T4と推定offset/delayを表示します。新しい表示は`ntp status`を再実行してください。専用フォームは追加せず、既存GUIのコンソールを使います。

基準時計は**ゲーム内のローカル時計（stratum 1相当）**です。実際のUTC、Minecraftの昼夜時刻、現実の日時を配信するものではありません。今回は基準サーバーとクライアントだけで、時刻の階層中継はしません。`ntp server on`はネットワークServerのみで、`ntp on`との同時有効化は拒否します。クライアントは8機種すべてで利用できます。

## ずれと周期の設定

```text
ntp offset 5000
ntp drift 50
ntp interval 30
ntp sync
ntp off
ntp target none
```

`offset`は表示時計のずれ（ms、±86,400,000まで）、`drift`は進み方の差（ppm、±1,000まで）です。既定は両方0。意図せず機器が故障する仕組みではなく、時計がずれる状況を試すための設定です。1000ppmならゲーム内1秒につき約1ms速く進みます。offset/driftの変更はその機器の動的補正を0へ戻し、ずれを新たに設定します。

`interval`は1〜3600秒（既定30秒）、20サーバーtickを1秒とします。`sync`は即時成功を返さず、同じ処理予算で次の同期を予約します。`off`は周期同期を止め、最後の補正を保ったまま時計を自走させます。`target none`は宛先を消去してOFFにします。宛先や周期を変えたときも、手動offset/driftを変えない限り表示時計を強制的に元へ戻しません。

T1=クライアント送信、T2=サーバー受信、T3=サーバー送信、T4=クライアント受信として、RFC5905の式を使います。

```text
offset = ((T2 - T1) + (T3 - T4)) / 2
delay  = (T4 - T1) - (T3 - T2)
```

方向別の仮想経路遅延から時刻を作ります。この版では基準Serverの処理時間を0とし、交換をメタデータとして評価して即座に補正します。実パケットを待つ処理や周波数を徐々に調整する制御ループではありません。往路・復路の遅延が非対称なら推定誤差が残り、サーバー内部の正解へ無条件に合わせる実装ではありません。

## 通信断・ACL・NAT

NTPはUDP123の**往復**です。pingが禁止されていてもUDP123を許可していれば同期でき、UDP123だけ拒否した場合は同期できません。戻りの経路/ACL、受信サービス、変換後の実ポートも検査します。

公開8123番を内部123番へ転送する例:

```text
nat forward add 1 udp 8123 192.168.10.20 123
```

クライアントでは、例えば`ntp target 203.0.113.1 8123`を指定します。NATの内外設定と経路は別途必要です。内部124番への誤転送、NTPサービス停止、返信不能の場合は補正しません。失敗した交換ではNAT変換表の作成や期限延長も確定しません。

状態の意味:

- WAITING: 有効だがまだ同期成功なし。失敗理由も表示します。
- SYNCED: 最近の成功を利用中。
- HOLDOVER: 同期失敗後、最後の補正で自走中。
- STALE: 最終成功から3周期以上が経過。正確な時計の保証ではありません。
- PAUSED: 機器自身の故障で同期を休止。LIMITはクライアント上限による休止。
- OFF: クライアント同期停止。REFERENCEはローカル基準サーバー。

処理上限で確認できない場合も時計を変えず、判定保留と表示します。通信が復旧すれば次の周期で再同期します。状態変化をNTPログとして記録しますが、毎回の正常な交換を大量にログ化しません。

## Syslogの時刻

従来の発生tick・受信tickに加えて、`clockMs=発生時計→受信時計`を表示します。送信時点で機器時計を固定し、配送時点で受信側の時計を固定します。**後から時計を合わせても過去の履歴や配送待ちログの発生時刻を変更しません。**

補正で時計が戻ることがありますが、履歴は受信番号の順に保持します。期限判定・配送待ち期限・履歴削除に補正時計は使いません。時刻だけでログを比較せず、機器名と単調tickも併用してください。履歴自体は従来どおりランタイムのみで、永続監査サーバーではありません。

## 保存・権限・上限

保存形式はv13。ON/OFF、基準サービス、宛先IP/ポート、周期、手動offset/driftを、機器の設定・装着品・故障・所有権とともに採掘アイテムへ保存します。旧v1〜v12はNTP OFF・offset/drift 0で読み込みます。設定バックアップにも含めます。補正値・最終同期・試料・予約は保存せず、再配置/再ロード後はローカル時計から再同期します。ダウングレードは保証しないため更新前バックアップを残してください。

設定・状態表示は既存メニューの管理権限に従います。`public on`はNTP設定編集を許可しません。NTPサービスへの時刻問い合わせはネットワーク側の経路/ACLで制御し、任意コードや機器管理権限を渡しません。暗号認証はないため、信用できる基準サーバーへ接続してください。

1ディメンション最大256クライアント、1tick最大2処理、1クライアント1予約です。失敗/停止中の期限確認も同じ予算です。`sync`の連打で予約が増殖せず、過去の未処理周期をまとめて送信しません。設定済み機器の再ロードで上限を越えた場合は当該機器だけLIMITとなり、空きができた後の`ntp on`で再登録できます。TPSの保証ではなく処理数とメモリの制約です。チャンクを強制ロードしません。

136種類の4/16幅ケーブル、全テクスチャ/モデル/レシピ・ゴーグル・タブは変更していません。既存アイコンのGUI/JEIガイドを4手順追加し、22トピック93手順になります。外部依存や新しいPayloadは追加せず、network-2を継続します。

## 今回含まない機能

複数基準の選択、階層中継、stratum選出、実NTPバイト形式、NTS/認証、時刻源の健全性判定、slew/PLL、うるう秒、IPv6、名前指定の宛先、時刻ベースのゲーム制御、実UTCへの同期は対象外です。
