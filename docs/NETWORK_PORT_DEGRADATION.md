# 接続を維持するポートの帯域劣化

機器・ポートの完全停止とは別に、**Link Upのまま実効帯域だけが低下する物理劣化**を追加します。OSや実ネットワークには接続しません。

## 手動試験と診断

機器GUIのコンソールで、管理権限のある機器に対して設定します。

```text
port 0 degrade
ports
show
```

`port 0 degrade` はP0を劣化させます。完全停止は従来の `port 0 fault`、本体全停止は `fault` です。完全故障したポートをdegradeで軽い故障へ戻すことはできません。同じ劣化を再指定しても、イベント・通信リセットを追加しません。

劣化時は **交渉速度の10%** が転送上限です。この倍率は現実のEthernet規格ではなく暫定ゲーム値です。例として、1Gbpsで接続した区間は100Mbps、固定100Mbpsの区間は10Mbps相当になります。管理ON/OFF、Auto/固定速度、光/銅線、VLAN、装着モジュールは書き換えません。固定速度の不一致など、本来Link Downになる条件はそのままです。

両端とも劣化していても10%を二重に掛けず、1区間につき1回だけ適用します。WAN上限はその後で計算します。例えば10Gbps光区間が劣化して1Gbps相当になっても、初期WANの20Mbpsが既に律速なら実効上限は20Mbpsのままです。ルート中の他リンクと機器の処理容量による制限、複数フローの帯域共有も適用されます。

`ports` はハードウェア/設定上限と劣化状態、`show`とポートフォームは接続区間の実効上限を表示します。ゴーグルもLink Upと実効上限を表示し、筐体は既存の故障用テクスチャを使います。故障ランプが赤でも、必ずしも全停止とは限りません。

```text
ping 192.168.1.20
transfer 192.168.1.20 100
flows
```

上記のように接続相手へのpingは通っても、100MBの仮想転送は遅くなります。監視のUPは帯域が正常という意味ではありません。実ファイル、追加のパケット配列、毎転送の乱数は作らず、帯域の数値として処理します。

## 修理・完全安定化

既存の修理キットで直せます。通常の右クリックは本体と全ポート、Shift+機器の面の右クリックはそのポートの完全故障または劣化だけを修理し、成功時に1個消費します。正常な面や権限外では消費しません。

管理OFFのポートを修理してもOFFのままです。`enable`、VLAN/速度変更、ポートモジュール交換、完全安定化の装着では既存の劣化を修理しません。設定フォームは最新の物理状態を保持し、古い画面や設定バックアップで無料修理できません。

完全安定化は、本体停止・ポート停止・帯域劣化の**ランダムな発生をすべて0%**にします。明示的な故障試験は可能です。劣化済みポートがさらにランダム故障の対象になった場合は、完全停止へ進みます。

## ランダム故障の配分

サーバー設定 `venusmod-network-server.toml` に `network.portDegradationShare` を追加します。既定0.5は、既存の `portFailureShare` によってポート故障を選択した後、未劣化の対象を帯域劣化にする割合です。0では従来のポート完全停止のみとなります。

**元の故障確率を増やしたり、6ポートごとに抽選したりしません。** `failureProbabilityPerDay` と1200tickの予約は維持し、故障の発生が決まった後で種類を選びます。本体停止中は追加抽選しません。割合0.5と劣化倍率10%は、プレイテストで調整するゲームバランス初期値です。

`PORT DEGRADED Pn` を重大度3で一度記録します。Syslogは残った実配線・経路・サービスの条件で配送し、毎tickに劣化ログを増殖させません。

## 保存・互換性・範囲

保存形式v16で6ポート分の劣化ビットを追加します。旧v1〜v15は「劣化なし」として読み込み、既存の本体/ポート故障は保持します。機器の通常ドロップ・再設置・ワールド保存では装着品・故障・所有権とともに復元します。設定バックアップは物理故障を含めず、復元先の**現在の**劣化/故障を維持します。ダウングレードに備え更新前のワールドバックアップを残してください。

既存と同じ物理ネットワーク単位の失効処理を使います。劣化・修理時には同じ物理網の転送/NATが再確立する場合があります。物理的に独立した別ネットワークの転送は維持します。パケット損失、再送、故障中の既存セッションの無停止継続を実装した意味ではありません。

レッドストーン端末の劣化だけでは出力を0にしません。既存のhold/stop/valueと有効な制御通信の期限に従います。通信量が少ない制御信号やpingだけでは、帯域劣化の影響が見えない場合があります。

136種類の4/16幅ケーブル、全画像・モデル・レシピ、ゴーグルの通信形式、クリエイティブタブは変更していません。GUI/JEI共通の既存強化・冗長化ページへ説明を追記します。参加クライアントとサーバーは同じ版を使ってください。network-3を継続します。
