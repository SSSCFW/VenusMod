# ボタンから実行する通信診断

機器を右クリックし、通常コンソール左下の「診断」を開きます。JEIは不要です。入力しただけ、画面を開いた/閉じた、ウィンドウを変更しただけでは通信を開始しません。

## 操作

- **Ping:** ゲーム内IPv4または名前へのICMP往復確認。例 `192.168.1.20`。
- **経路確認:** 同じ往復確認に加えて、既存`trace`の機器経路を表示。実TTL探査のtraceroute完全再現ではありません。
- **名前解決:** 設定済みゲーム内DNSへ名前を問い合わせます。例 `base.local`。逆引き・IP指定は未対応です。
- **転送開始:** 1〜1,000,000の整数MBとlow/normal/highを指定して仮想転送を開始。必要なら宛先に`:ポート`を付けます。省略時は既存の仮想転送ポート5000。実ファイルは作りません。
- **転送一覧:** 自機が送信元の転送ID・進捗・相対優先度・最終割当帯域を取得。再クリックで更新します。停止/途中変更は従来のCLIを使用します。

入力例は仮想ネットワークの設定を作りません。機器IP、配線、VLAN、名前を使う場合のDNS、ルーティング・ACL・NATは従来どおり必要です。返送できなければ失敗します。名前解決が通ってもWebの稼働やレッドストーン出力は確認しません。

## 結果・入力の扱い

上部の「送信」は要求を送ったことだけを表し、通信成功を意味しません。結果欄は通常コンソールと共有する**最後のサーバー表示**です。今回の応答が届くまでは前回の結果が残ります。入力エラーでは「未送信」を表示し、前回の結果を消したり新しい成功に置き換えたりしません。長い結果はホイールでスクロールできます。

宛先・転送量はそれぞれ検査します。Ping/経路/名前解決は転送量の誤入力に影響されず、転送一覧は宛先なしで使えます。URL、改行、複数命令は送れません。Ping/経路/名前解決にポートは付けられません。転送の宛先名が`priority`や`cancel`でも、明示的なサービスポートを付けて生成しCLI管理命令と混同しません。

画面内ではTabで操作部品を移動し、Esc/戻るで通常コンソールへ戻ります。入力欄でEnterを押しただけでは送信しません。ボタンへのフォーカス後にEnterで実行できます。入力途中の宛先・量・優先度は同じ画面内でのリサイズやガイド往復で保持します。GUIを閉じて再び開いた場合の永続保存ではありません。

「ガイド」から共通の基本/ポート設定ページへ移動できます。同じ説明はJEIの接続ガイドにも含みます。既存の23トピック97手順は維持し、長文カードを必要に応じて分割します。

## マルチ・負荷・互換性

背後のモジュール枠・プレイヤーInventory・CLI・JEI入口へ診断操作を渡しません。既存のCommand Payloadとサーバー側の開いたメニュー、距離、所有/共有権限、レート制限を使用します。クライアントの入力検査だけで認可する仕組みではありません。

実行ボタンには10クライアントtickの連打抑制がありますが、サーバーの上限は別途適用されます。定期的にpingや転送を送りません。結果の折り返しは受信テキストまたは画面が変わった時だけ更新します。外部ネットワーク、OSシェル、Webブラウザーは使用しません。

保存v16・network-3、136種の4/16幅ケーブル、画像・モデル・レシピ、装着品・故障・所有権の引継ぎは変更しません。クライアント/サーバーは同じMOD版を使用してください。実際の検証範囲は [NETWORK_DIAGNOSTICS_GUI_VERIFICATION.md](NETWORK_DIAGNOSTICS_GUI_VERIFICATION.md) を参照してください。
