# ネットワーク機能 — 初期実装と使い方

> 追加実装: [OSPF](NETWORK_OSPF.md)、[ACL/DHCPリレー](NETWORK_SERVICES_GUIDE.md)、[NAT/NAPT](NETWORK_NAT.md)、[VRRP広告・タイマー](NETWORK_VRRP.md)、[Classic STP](NETWORK_STP.md)、[配線の局所更新](NETWORK_TOPOLOGY.md)。以下は初期段階の記録を含みます。現行の対応範囲は各機能の説明を参照してください。

対象はMinecraft 1.21.1 / NeoForge 21.1.x。Createは不要、JEIは任意です。全体計画は [NETWORK_SYSTEM_SPEC.md](NETWORK_SYSTEM_SPEC.md) を参照してください。**本書は初期実装を記録するもので、設計書全体の完成を意味しません。**

## 追加するもの

4/16ブロック幅のLAN・光ケーブル8種類、PC、L2/L3スイッチ、ルーター、ONU、OLT、サーバー、レッドストーン通信端末、18種類の部品・強化・修理・診断アイテムを追加します。各機器の前面・側面・上下面・ポート・故障表示、全ケーブル、部品アイコンには独自テクスチャがあります。画像はIC2から転載していません。

ケーブルは中央の細い芯から接続方向へ腕が伸びます。モデルだけでなく選択・衝突形状も細くし、隣接ブロックの面を隠さない形にしています。途中のT字分岐は通信不可です。分岐にはスイッチを挟んでください。異なる種類のケーブル同士の直結も行いません。

### ケーブルの16色染色と帯域表示

既存の無染色ケーブル8種類を残し、それぞれにMinecraft標準の染料16色を用意します（合計136種類）。これら136種類は**専用の「ネットワークケーブル」クリエイティブタブ**に集約し、元のVenusModタブにはネットワーク機器・強化部品・ゴーグルのみを残します。作業台に**ケーブル1個 + 希望色の染料1個**を置くと1個染色できます。既に染色したケーブルを別の色へ再染色することもできます。設置済みケーブルに染料を持って右クリックしても再染色できます（クリエイティブでは染料を消費しません）。

接続条件は**同じ規格かつ同じ色**です。青色と赤色、青色と無染色、Cat5eとCat6などは接触しても腕がつながらず、通信リンクも生成されません。無染色は無染色同士のみ接続します。機器の各面には色を問わずケーブルを接続でき、複数の異なる色を別ポートへつなぐことは可能です。

ケーブルのアイテムにマウスを重ねると**最大伝送帯域、最大配線長、色別接続条件**を表示します。最大伝送帯域はケーブル規格の理論上限であり、実効通信速度は両端ポート・モジュール・機器内部容量・WANなどに依存します。既存の帯域定義（Cat5e 1Gbps / Cat6・Cat6A・OM3 10Gbps / Cat8・OM4 40Gbps / OS2 100Gbps / 金星特殊光400Gbps）は染色によって変わりません。

## 最初の通信

PCを2台とL2スイッチを設置し、それぞれをCat5eケーブルで接続します。ケーブル区間は機器間の独立した1本にしてください。機器を右クリックすると設定GUIが開きます。

PC-Aで入力:

```text
ip 192.168.1.10/24
```

PC-Bで入力:

```text
ip 192.168.1.20/24
```

PC-Aで通信確認:

```text
ping 192.168.1.20
trace 192.168.1.20
transfer 192.168.1.20 100
flows
```

`transfer`の最後の数値は仮想MBです。実ファイルを作ったり現実のネットワークへ送信したりせず、帯域共有と転送進捗を計算します。`trace`はこの版では機器経路の表示で、実機のTTLプローブによるtracerouteとは異なります。

## ポートと強化

初期版は全機種6面ポートです。`P0=北、P1=東、P2=南、P3=西、P4=上、P5=下`。前面の向きを変えても番号は世界方位に固定です。8/24ポート筐体はまだありません。

GUI下部の左6枠はポート専用強化、中央6枠は本体強化、右1枠はWAN強化です。モジュールは装着・取り外し可能で、各ポートの上限は独立しています。

```text
ports
port 0 speed 100m
port 0 speed auto
port 0 vlan 10
port 1 mode trunk
port 0 disable
port 0 enable
```

標準は1Gbps。10G/40G/100G/400Gモジュールで上限を増やします。速度はケーブル・両端ポート・内部処理容量・WANの最も遅い部分に制限されます。本体の標準容量は6Gbps、転送処理モジュール1枚ごとに4倍、上限768Gbpsです。バッファ1枚で送信元の同時仮想転送枠を4増やします（標準4、全体上限128）。

光に接続する通常機器では10G以上の対応モジュールを装着し、両端で設定します。

```text
port 0 media fiber
```

ONU/OLTの北側P0は標準で光対応です。銅線へ戻すときは`port 0 media copper`を使います。

## L3・DHCP・DNS

ルーターの初期P0は192.168.1.1/24、P1は192.168.2.1/24です。端末は各LANに合わせて設定し、外のサブネットへ送る際のゲートウェイを指定します。

```text
gateway 192.168.1.1
port 1 ip 192.168.2.1/24
route add 10.0.0.0/24 via 192.168.1.2 port 0
routes
```

ルーターは標準で簡易DHCPが有効です。端末から`dhcp`を実行すると到達可能なDHCP装置へ問い合わせます。DHCPリレーと配布予約は追加実装済みです。リース更新タイマーは未対応です。

```text
dhcp-server on
dns-record base.local 192.168.1.20
```

端末側:

```text
dns 192.168.1.1
nslookup base.local
```

## WAN・故障・冗長化

この版でWAN帯域制限が付くのは**ONUとOLTを直接結ぶ論理リンク**です。初期20Mbpsから両端のWANモジュールによって100Mbps、1Gbps、10Gbps、100Gbps、400Gbpsに強化できます。両端・光ポート・本体容量も対応している必要があります。ISP契約やPONスプリッタはまだ実装していません。

レシピは金を大量に使う多段階クラフトです。上位モジュールが複数の下位モジュールを消費するため、最上位ほど総素材量が大きくなります。金星素材には既存のヴェネサイト・ニッケルを利用し、金星核・金星魂石など進行キーは消費しません。設計書の素材表は暫定で、実際の必要数はレシピ/JEIが正となります。

内部故障率は標準で稼働24,000tick当たり0.05%。`world/serverconfig/venusmod-network-server.toml`の`failureProbabilityPerDay`で調整でき、0で無効です。完全安定化モジュール装着中は内部ランダム故障率が0%になります。切断や外部要因まで防ぐものではありません。

手動試験は`fault`、修理はネットワーク修理キットで右クリックです。採掘して置き直しても故障状態は残ります。

`stp on`は選択中の方式を有効にします。初期値のsimpleは即時の簡略木方式、`stp mode classic`はBPDU・役割・タイマーで選出する方式です。VRRPも広告・期限によるMaster/Backup選出へ更新済みです。`vrrp 192.168.1.254 120`とLAN側の担当ポートを設定し、同じVIP・VRIDの広告で役割を決めます。RSTP、IPv6 VRRPや複数グループ等は未対応です。詳しくは [STP](NETWORK_STP.md)、[VRRP](NETWORK_VRRP.md) を参照してください。

## 安全な設備操作と権限

サーバーで`web on`を設定して、端末で`open IPアドレス`を実行すると固定のゲーム内状態表示を返します。これは実ブラウザーでもHTTPサーバーでもありません。

レッドストーン通信端末にIPを設定すると、所有者・共有者から`redstone IP 15`で遠隔出力できます。出力は0〜15、通信の往復到達性を確認した後に適用します。

`trust プレイヤー名`でオンラインのプレイヤーへ管理権限を共有し、`untrust プレイヤー名`で解除します。共有変更は所有者または管理者のみです。`public on`は遠隔サービスを公開し、機器の設定画面を公開する操作ではありません。

## 保存・ガイド・現在の制約

通常採掘で機器アイテム1個に設定・装着モジュール・所有権・故障状態を保存します。シルクタッチは不要です。動的MAC/ARP表と通信中フローは再構築します。同時に配置される複製機器は機器IDを分けます。

GUIの「ガイド」から接続例・コマンド・制限を読めます。ホイールで説明部分をスクロールできます。JEI導入時は機器・ケーブル・強化アイテムの情報ページにも説明を登録します。**GUI/JEI共通の専用構成図カテゴリを追加実装済みです。Create Ponderのような3Dアニメーションは未実装です。**

初期版の注意点:

- 物理配線はロード済みチャンクだけで解析し、チャンクを強制ロードしません。途中のケーブル区間がアンロードされた場合も通信は休止します。保存済み配線で未ロード区間を常時中継する機能は未実装です。
- 配線の局所更新を追加しました。変更したケーブル区間だけを再解析し、物理的に独立した別ネットワークの転送・NAT・OSPF/VRRP/STPを保持します。同じ物理連結成分の通信は安全のため再確立する場合があります。全体上限やチャンク中継の制限は [局所更新の説明](NETWORK_TOPOLOGY.md) を参照してください。
- MAC/ARP学習表を記録しますが、転送処理はVLANを考慮した経路探索で、実Ethernet/TCPスタックの完全なフレーム単位再現ではありません。
- 単一エリアOSPF、ACL、DHCPリレー、NAPT/ポート転送は追加実装済みです。BGP、IPv6、IPsec、LACP、複数エリアOSPF、8/24ポート、光分岐、惑星間通信、カメラ映像、物流搬送、ファイル/メール/認証サーバーは未実装です。未対応CLIは成功したふりをせず拒否します。

## 検証

初期版では独立したJavaテスト47アサーションと、生成された174 JSON・74 PNGの参照/画像寸法/全方向モデル/4/16幅の静的検査を実行しました。16色対応ではケーブル128種類を追加し、生成PNGは202個になります。すべての染色レシピ・ブロックステート・アイテムモデルをJDK検査対象としています。`gradle check`にも純JavaテストとJDK版アセット検査を登録しています。

実BlockStateの全ケーブル状態および実ItemStackでの機器ドロップ・保存・再配置を確認するGameTestを追加しています。**全体ビルドとGameTestの合否は該当コミットのGitHub Actionsを確認してください。初期作成時点では未確認です。** 手動の実クライアント表示、JEI画面、シェーダー併用、複数人による実操作、大規模TPS負荷測定は未実施です。

## VRRP広告・タイマー

簡略VIP選出を、Master/Backupの広告・期限・preempt・仮想MAC・広告ACLの方式に更新しました。旧形式の設定と細いケーブルは維持します。手順と制限は [VRRPの構成と使い方](NETWORK_VRRP.md) を参照してください。従来の「VRRP広告タイマー未対応」という記述はこの更新より前の実装状況です。

## STP追加段階

BPDUでの選出とタイマーを使う`stp mode classic`を追加しました。従来の即時方式はsimpleとして残り、初期値もsimpleです。接続する全L2機器でclassicを選択してください。Root/Designated/Alternate、Listening/Learning/Forwarding、cost/priority、edge/guard、保存v6に対応します。[NETWORK_STP.md](NETWORK_STP.md) に操作・混在接続・物理配線変更時の制限を記載しています。上記の初期実装記録の「STPは簡略方式のみ」はこの追加により更新されます。
