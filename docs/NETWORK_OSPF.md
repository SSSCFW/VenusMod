# OSPF: エリア内の動的経路学習

Minecraft 1.21.1 / NeoForge。全体設計は [NETWORK_SYSTEM_SPEC.md](NETWORK_SYSTEM_SPEC.md)、既存のACL・DHCPは [NETWORK_SERVICES_GUIDE.md](NETWORK_SERVICES_GUIDE.md) を参照。

今回追加するのは **OSPFv2を参考にした単一エリア内のサブセット**。Helloの送受信、双方向確認、DB同期、Router-LSA配布、各ルーターのLSDBからのSPF計算、Dead失効をJavaで処理します。全プロトコルを完成したとは扱いません。

## 使い方

3台のルーターを三角形に接続し、A側とC側にPCを置く例です。ポート番号は配線した面に合わせます。以下はA–BをP1、A–CをP2、PC側をP0としたAの設定例です。

```text
port 0 ip 192.168.1.1/24
port 1 ip 10.0.12.1/24
port 2 ip 10.0.13.1/24
ospf router-id 1.1.1.1
ospf area 0
ospf port 0 passive
ospf port 1 on
ospf port 2 on
ospf cost 0 1
ospf cost 1 10
ospf cost 2 50
ospf on
```

B: Router IDを2.2.2.2、A側を10.0.12.2/24、C側を10.0.23.2/24にし、両ポートをon・cost 10にします。C: Router IDは3.3.3.3、B側10.0.23.3/24 cost 10、A側10.0.13.3/24 cost 50、PC側192.168.3.1/24をpassive・cost 1にします。すべてArea 0。

PC-Aは192.168.1.10/24、gateway 192.168.1.1。PC-Cは192.168.3.10/24、gateway 192.168.3.1です。静的経路を手入力しなくても、収束後にPC間で通信できます。

```text
ospf neighbors
ospf database
ospf routes
show ip route
show ip ospf neighbor
```

同じプレフィックスなら直結・静的経路がOSPFに優先します。プレフィックス長が異なる場合は最長一致です。学習経路は`O`、直結は`C`、静的は`S`で確認できます。`show ip route`のC/Sは設定の一覧を含みます。

**passive**はLANのプレフィックスを広告しつつHelloを送らない設定です。`off`はOSPFへの参加と広告を停止します。`ospf off`で機器全体のOSPFを止めます。旧機器へOSPFを勝手に有効化しません。

## 隣接・コスト・タイマー

同じエリア、同じサブネットとプレフィックス長、同じHello/Dead設定が必要です。Router IDは稼働OSPF機器内で一意にします。明示しない場合は設定IPの最大値を使いますが、初期ルーターのIPが重複するので明示設定を推奨します。

既定はゲーム向けにHello 1秒、Dead 4秒（20/80tick）。変更例:

```text
ospf timers 2 8
ospf cost 1 auto
```

Helloは1〜60秒、DeadはHelloの2倍以上〜240秒。`auto`のコストは基準100Gbpsをリンク帯域で割って切り上げ、1〜65535に制限します。手動のコストも1〜65535です。高速ポートやWAN強化が経路選択に影響します。

初回Helloを受信するとINIT、自分のRouter IDが相手のHelloに載るとEXCHANGE、圧縮したDB同期を双方で終えるとFULLになります。FULLの隣接だけをリンク情報として広告します。経路計算は機器ごとに受信したLSDBのみを使用し、全ワールドの構成から未学習の経路を作りません。

故障・停止・一方向遮断でHelloが消えると隣接が失効し、別経路を再計算します。ローカルのLink Downは再設定時に反映、相手のHello消失はDeadで検出します。修理すると再度Hello/DB同期を経て安い経路へ戻ります。切替は瞬時・無損失ではなく、経路変更に巻き込まれた仮想転送は中断・再送になります。

## ACL

OSPF用のプロトコル名`ospf`を追加しました。TCP/UDPのポート番号ではありません。

```text
acl add 1 in 10 permit ospf any any
acl add 1 in 20 permit ip any any
```

`deny ospf`にすると他のIPv4通信は許可したままOSPFの隣接だけを失わせる試験ができます。現段階のHello/DB同期/LSUはすべて224.0.0.5宛ての仮想OSPFメタデータとして既存L2経路・出入ACLを判定します。実UDP、ソケット、外部LANには接続しません。

## 保存・ガイド・表示

設定フォーマットをv3に拡張し、v1/v2を読み込めます。Router ID、エリア、参加ポート、passive、コスト、タイマーは採掘した機器アイテムに保持します。学習経路・LSDB・隣接は永続設定と分離しており、再配置/再起動後に再学習します。旧版へ戻す前提の互換ではないためワールドのバックアップを残してください。

GUI/JEI共通ガイドに「OSPFで経路を自動学習」を追加。既存のテクスチャ付きルーターアイコンで三角形の構成を示します。全ケーブルの4/16幅・既存の74 PNG・ブロックモデル・レシピは変更しません。テクスチャの有無と実クライアントでの目視確認は区別します。

## 軽量化と範囲

1ディメンションの有効OSPFは128機器、各機器32ネイバー、LSDB128広告まで。イベントキューは16,384件、1tickに最大64イベント、SPFは最大2回・各32,768作業単位です。キュー/構成上限を超えるとOSPFを停止し、無制限に処理しません。修正後の設定変更で再開できます。

L2/VLAN/ACLの隣接探索は構成変更時に最大2ポート/tickで分割・キャッシュします。通常のHelloではキャッシュを使用します。LSAは30秒ごとに更新、2分でMaxAge失効。最短の期限だけを予約し、全LSAを毎tick走査しません。

物理配線変更時は既存のNetworkWorldがトポロジーを再生成するため、現段階ではOSPFも再学習になります。機器設定/故障変更ではエンジンを保持して状態遷移します。未ロード区間の中継、局所再計算、全体の大規模TPS最適化は従来の残項目です。

**今回の対象外:** ABR/複数エリア間経路、DR/BDR、認証、外部経路再配布、ECMP負荷分散、DD/LSR/LSAckの全ワイヤ形式・全再送状態。全隣接型・圧縮DB同期によるゲーム用実装です。等コストはポート番号等で1経路に決定します。BGP/IPv6/NAT/LACP等の残機能も今回完成扱いしません。

一次仕様の参照: [RFC 2328](https://www.rfc-editor.org/rfc/rfc2328.html) §10（隣接）、§12–14（LSAとaging）、§16（SPF）。上記の省略点・ゲーム時間は本MOD独自です。
