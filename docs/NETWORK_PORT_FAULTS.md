# ポート単位の故障と個別修理

機器全体の停止とは別に、各ポートの物理故障を追加します。P0が故障しても機器本体やP1〜P5を故障扱いにはしません。ポートの管理ON/OFF、速度、VLAN、光/銅線、装着モジュールはそのまま保持します。

## 故障試験と表示

機器を右クリックしたGUIのコンソールで、例えば次を実行します。

```text
port 0 fault
ports
show
```

`port 0 fault`はP0だけの手動故障試験、従来の`fault`は本体全停止です。自分または共有された機器の管理権限が必要です。完全安定化モジュールはランダム故障を防ぎますが、明示的な故障試験は妨げません。同じ故障を再指定しても再発イベントや通信の再初期化は発生させません。

故障ポートはケーブルがつながっていてもLink Downとなり、送受信・VLAN中継・ルーティングプロトコルのリンクとして使いません。GUIの状態見出しと`ports`には具体的なP番号、ポート設定画面には「ポート故障」、対向側には「対向機器/ポート故障」を表示します。未配線でも自ポートの故障を確認できます。

筐体は既存の赤い故障表示を使います。赤い表示は「本体またはいずれかのポートに故障あり」という意味で、全停止とは限りません。ゴーグルの機器警告も同様で、ポートのリンク状態を併せて確認してください。故障の詳しい部位はGUI/コンソールで読めます。

`port 0 enable`、速度変更、VLAN変更、モジュールの交換では修理しません。設定フォームを故障前から開いていた場合も、適用時には最新の物理故障状態を保持します。

## 修理キット

- **通常の右クリック:** 機器本体と全ポートを修理します。キット1個を消費します。
- **Shift+機器の面を右クリック:** クリックした面のポートだけを修理します。キット1個を消費します。本体や他のポートの故障は残ります。

P0=北、P1=東、P2=南、P3=西、P4=上、P5=下です。番号は機器の前面の向きではなく世界方位に固定です。健康な部位、権限外、操作距離外、空のキットでは修理/消費しません。クリエイティブでは既存どおりアイテムを消費しません。

修理しても管理OFFのポートはOFFのままです。VLAN、固定速度、許可リスト、IP、モジュール、所有権は変わりません。正常になった最後の故障を修理すると、筐体の表示も正常へ戻ります。

## ランダム故障とバランス

既存の`venusmod-network-server.toml`に`network.portFailureShare`を追加しました。既定0.75は、故障が発生すると決まった後に75%の割合でポート故障を選ぶ設定です。0なら従来の本体停止だけ、1なら可能な限りポート故障を選びます。**ゲームバランス用の暫定値**です。

故障発生そのものの基礎確率`failureProbabilityPerDay`、1200tickごとの予約判定、安定化50%/90%/100%の効果は維持します。ポートを6個別々に抽選して故障確率を6倍にする方式ではありません。故障候補は管理ONかつ未故障のポートです。候補がなければ本体停止となり、本体が既に停止中なら追加抽選しません。

完全安定化の装着中、および`failureProbabilityPerDay=0`では、**本体とポートのランダム故障はどちらも0%**です。既に発生した故障を装着だけで修理する機能ではありません。1台で複数のポート故障が累積することはあります。

故障時には`PORT FAULT Pn`、修理時には`PORT REPAIR Pn`または`REPAIR`を既存ログへ記録します。Syslogの送信は残った配線と既存の通信条件に従い、送信経路まで壊れていれば届きません。故障イベントを記録したことと、収集サーバーに届いたことは別です。

## 冗長化と安全出力

正常な別ポートは使えますが、代替経路がなければ通信は復旧しません。simple/classic STP、OSPF、VRRP等は共通のリンク成立判定に従い、故障ポートを使わず再収束します。Classic STPはBPDU・Forward Delay等の待ち時間を省略しません。

この版では故障/修理も既存の物理成分単位の失効を使います。**独立した別物理網の転送は維持**しますが、同じ物理網の転送やNAT表は再確立する場合があります。無停止の既存TCPセッションやNAT状態同期を保証する機能ではありません。

レッドストーン通信端末のポート故障は、本体故障と異なり、それだけで出力を即座に0にはしません。holdなら最後の出力を保持し、stop/valueなら従来の制御更新期限によって安全値へ移行します。本体自体が故障した場合の出力0は従来どおりです。

## 保存・復元・互換性

Profile v15の末尾に6ポート分の故障ビットを保存します。旧v1〜v14は「ポート故障なし」として読み込み、旧データの本体故障はそのままです。通常採掘・ドロップ・再設置・ワールド保存で装着品、設定、所有権とともに引き継ぎます。ダウングレードは保証しないため、更新前バックアップを残してください。

**設定バックアップで物理故障を巻き戻すことはできません。** 設定の控えに故障状態を含めず、復元時には現在の本体・各ポートの故障を保持します。故障前の控えを使っても無料修理にはなりません。

GUIの許可編集フィールドやPayload形式は変更せず、network-3を維持します。参加クライアントとサーバーには同じMOD版を使用してください。136種・4/16幅のカラー/無染色ケーブル、全テクスチャ/モデル/レシピ、クリエイティブタブは変更していません。既存のGUI/JEIガイドの強化・冗長化ページへ説明を追加しました。

## 範囲
