# STP BPDUの検証記録

## 純Javaでの実行

変更前の公開APIで`stp mode classic`が未対応で失敗することを確認し、独立した状態機械・設定・通信への統合を実装しました。Java21で全ネットワーク検査を再コンパイルしています。

| 検査 | 結果 |
| --- | --- |
| STP公開コマンド契約 | 3項目成功 |
| BPDU・状態機械・root/port ID・期限 | 27項目成功 |
| 通信経路・MAC学習・故障・混在方式・ACL | 49項目成功 |
| 保存v5→v6・誤入力・不正BPDU・有限期限 | 57項目成功 |
| 共通GUI/JEIガイド | 14トピック・135検査・52手順 |
| 既存ネットワーク・NAT・OSPF・VRRP・ACL/DHCP | 全試験成功 |
| 既存アセット | 174 JSON・74 PNG、全参照解決 |

新規STPは合計136検査です。期限の境界試験では1000回のBPDU更新後も期限が上限内であることを調べていますが、1000個の独立した機能試験とは数えていません。

検査中に「cost編集でBPDUを受信済みのedgeが再び即時転送になる」問題と、「ポートコストの最大値を経路無効値と誤って共用する」問題を再現して修正しました。不正なcost=0や負VLANの削除要求も拒否し、既存設定を維持します。旧版入力は変更前の実v5コードで作った固定fixtureを使っています。

## 実ブロック試験とCI

新しいNetworkStpGameTestsは2件です。3台のスイッチ・2台PCを実ケーブルで接続し、起動待ち、低コスト経路、Blocking中のBPDU受信、故障後の待機、予備経路、修理、実ケーブル破壊と再配線を通常のサーバーtickで検査します。別試験ではBlock.getDropsで方式・priority・VLAN上書き・各ポート・タイマー・モジュール・故障・所有権を保存復元します。

**この文書の初回作成時点では、追加コードの全体ビルドと新規GameTestのCI結果は未確認です。** 既存Build 1.21.1 NeoForgeの該当コミットで結果を確認後に追記します。

## 未実施・制限

実クライアント目視、JEI実操作、シェーダー併用、複数人の実操作、大規模TPS測定は未実施です。独立したレビュー用サブエージェントは使っておらず、自己レビューと試験で確認しました。

既存のsimpleを維持し、classicは明示的に選ぶ設計です。RSTP/PVST/MSTワイヤ互換・TCN等の未対応範囲は [NETWORK_STP.md](NETWORK_STP.md) に記録しています。ケーブルの4/16幅・既存テクスチャ・レシピは今回変更していません。
