## 失敗先行と純Java

公開CLI `port 0 fault`が未対応で失敗、新しい物理故障モデルが存在せずコンパイル失敗、共通ガイドに操作例がなく失敗することを確認してから実装しました。

| 新規テスト | 検査数 |
| --- | ---: |
| PortFaultContractTest | 3 |
| PortFaultModelTest | 29 |
| PortFaultNetworkTest | 25 |
| PortFaultCodecTest | 47 |
| PortFaultGuideTest | 7 |

合計111検査。全86個のネットワーク純JavaテストクラスをJava21で再コンパイル・実行して成功しました。抽選の乱数はモデル試験で決定的な値を渡し、機器/ポートの選択・完全安定化・管理OFF・候補なし等を確認しています。実サーバー上で確率頻度を統計測定したという意味ではありません。

通信試験は公開コマンド→実際のリンク成立判定を使い、故障ポートの拒否、正常なポート対の到達性、独立物理網の転送保持、simple STPの迂回、enable/モジュール交換/フォーム編集による無料修理の防止を確認します。

旧v14 fixtureは変更前の実クラスで生成した固定文字列です。v15のポート故障を全8機種で往復し、未知の故障ビット・切断・余分な保存データの拒否を検査しました。既存試験は現在書出し形式の期待値のみv15へ変更し、旧fixtureと個別の設定値検査を残しています。Syslog severity/NTP drift/許可VLANの破損検査は、新しい末尾1byteを考慮して元の対象を壊すようにしています。

アセット生成・参照検査は1,594 JSON・204 PNGで成功。画像・モデル・レシピ生成器は無変更です。既存ガイドの22トピック93手順を維持しています。

147件は既存機能を含むリポジトリ全体の件数で、今回のポート故障GameTestは3件です。通常の青色ケーブルから通信し、公開CLIでのポート故障、正常ポート対の通信維持、実メニューの所有者・権限外操作、正常箇所でのキット未消費、Shiftの面別修理と1個消費を確認しました。別試験でBlock.getDropsによる故障・装着品・VLAN・所有権の保存、設定復元で故障を直さないこと、個別修理が本体故障や管理OFFを変更しないこと、全修理を検査しました。3つ目はClassic STPのBPDU/Forward Delayを含む実配線の迂回と、実修理Itemを使った後の低コスト経路への復帰です。模擬プレイヤーによるサーバー側のuseOn検査であり、人がShiftを押してマウス操作した検証とは区別します。

作業中に同じブランチへ入った閻魔刀の10コミット・9ファイルを保持し、`77c3ed2`を親に変更を重ねました。変更箇所の重複がないことと、31ファイルのアップロードが純Java検査済みの内容と一致することをpush前にGit blobで確認しています。CI診断スナップショット内の同じ31ファイルも一致しました。

検証環境はJava21、Minecraft1.21.1、NeoForge21.1.235、Create6.0.10です。JEI/SlashBlade本体はこのGameTest環境にはなく、既存のSlashBlade実体依存検査の一部はスキップされています。任意の通常専用サーバースモークテストは今回実行せず、GameTestサーバーでの検査とは区別します。

`ci-latest`の`VenusMod-1.21.1.jar`が検証対象コミット向けに公開されたことも確認しました。公開時SHA-256: `836297c1cd9bda00aa5fe76859db32dcf0424818dc53be7940856d8966c4f921`。このリリースは後続の成功ビルドで上書きされます。
