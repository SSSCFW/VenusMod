## 中断原因と修正

`3230623` / run `39399165625` ではBuild・GameTestは成功しましたが、実JEI入力試験は `java.awt.AWTException: headless environment` で停止しました。診断artifactのFAIL.txtから、ゲームプロセス内の `new Robot()` が原因箇所であることを確認しました。

修正コミット `81cd68c98d77005a98b53c19bac728cca02e090d` は、ゲーム側のAWT設定やキャッシュを変更せず、同じ隔離Xvfb DISPLAYの別JVMにネイティブ入力を委譲します。固定された標準入力パイプだけを使用し、外部サービスやネットワークの待受は追加しません。要求長・座標・許可キー・応答待ちには上限があり、成功/失敗とも入力用プロセスを閉じます。

新しいbridge APIが存在しない状態で検査のコンパイル失敗を確認してから実装しました。親をheadlessのままにすると従来のRobot生成は失敗する一方、新方式の起動と終了は成功することを、ローカルとCI両方の11検査で確認しています。通常プレイでは開発フラグがなく、production判定・専用ディレクトリ・fixture確認により、この試験は実行しません。

参考: [Java21 Robot API](https://docs.oracle.com/en/java/javase/21/docs/api/java.desktop/java/awt/Robot.html)。画面イベントハンドラーを直接呼ぶことで入力成功を作る修正ではありません。
