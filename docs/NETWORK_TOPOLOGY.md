# 配線の局所更新と通信状態の保持

Minecraft 1.21.1 / NeoForge。承認済みネットワーク仕様の「イベント駆動・局所更新・マルチプレイでの負荷抑制」の実装です。新しいプロトコルや機器は追加していません。

## 変わったこと

以前は1本のケーブルを変更しただけでも、同じディメンションの通信エンジンを作り直していました。この更新では**同じエンジンを維持し、変更位置に関係するケーブル区間だけを再解析**します。

```text
拠点A: PC ─ Router ─ Server  （転送・NAT・OSPF/VRRPを維持）

拠点B: PC ─ Cable × Cable ─ PC  （切断区間だけを再解析）
```

両拠点が物理的に独立している場合、Bの配線変更でAの通信を中断しません。NATのエントリー/期限、MAC/ARP表、OSPFの学習経路・隣接、VRRPのMaster/Backupと時計、STPの状態を維持します。別拠点のSTP/VRRPの状態変化も無関係な転送を消去しません。

変更位置に接続していた論理リンクは**設置/破壊イベント時に即時撤去**し、予算付きの再解析が完了してから有効なものだけを公開します。解析途中でも確認済みの他区間は使え、プロトコルのタイマーと仮想転送も進みます。解析中にさらに編集しても古い結果を公開しないよう、当該区間だけ再検査します。

## 無効化の単位と残る制限

転送/NATの無効化は、安全側に**物理的な連結成分単位**で行います。VLANやルーター設定で分かれていても、ケーブルで連結しているネットワークは同じ影響範囲に含まれます。物理網を結合する際には結合後の両側、切り離す際には分割前の両側を対象とします。使用していない予備配線の変更でも、同じ物理網のフローは再確立が必要になることがあります。

これはフロー単位の最小失効や、完全に無停止のネットワーク変更を保証する仕組みではありません。別物理網を保護しつつ、古い経路/NAT情報を誤って使わないための保守的な実装です。

ケーブル切断後も通信エンジン自体は捨てません。変更のない機器のプロトコル時計は進み続け、該当ポート/経路だけが変わります。ただし、実際に担当ポートを失ったVRRP機器や、再設置された機器が再確立するのは正常な挙動です。NAT状態同期やRSTPの追加ではありません。

未ロードチャンクのケーブルを保存情報だけで中継する機能は**まだ未実装**です。アンロード時には依存する区間を停止し、再ロード時にその区間を再解析します。未ロード位置を参照したり、ネットワークのためにチャンクを強制ロードしたりしません。

## 操作と診断

通常は追加設定不要です。機器GUIの状態欄に、接続数、不成立区間数、索引中のケーブル数、局所解析中/待機を表示します。

```text
topology
```

上記コマンドは解析状態と今回tick/累計の作業数を表示します。作業数はCPU時間やTPSではありません。

索引・待ち行列の上限を超えた場合は、明示的な上限エラーで既知リンクを停止します。配線を減らした後、**サーバー管理者のみ**が機器GUIで次を実行できます。

```text
topology rebuild
```

これは例外的な全配線再発見です。通常の編集では不要であり、全体再解析時の通信維持は保証しません。一般プレイヤーがこの操作で他拠点の通信を切ることはできません。

不正な`ip`/`port`等のCLI入力で、設定を戻すためだけに正常な転送やNAT表を消去していた問題も修正しました。設定コピーを検証し、成功した変更だけを反映します。

## 処理量と保存

- ケーブルBlockEntity/Tickerは追加していません。1区間の索引とチャンク依存を持ち、編集位置と6近傍から影響区間を引きます。
- 1回の解析作業は最大1ケーブルと6近傍の参照です。`topologyWorkPerTick`（既定512、設定範囲32〜4096）で実行作業数を制限します。旧区間の掃除や再走査の種も分割します。
- 索引は最大131,072ブロック、直接の変更待ちと再走査作業列はそれぞれ131,072以下、ロード待ちも131,072以下です。上限で無限に追加せず明示停止します。
- 制御プロトコルの設定検証や単純STPの計算には、従来のディメンション共通上限が残っています。VLAN数128やプロトコル機器数などの**全体上限超過**まで別網へ無影響になる保証ではありません。
- 保存形式はv6のままです。機器設定・装着品・故障・所有権の採掘/再設置保持を変更していません。動的な接続索引はワールド起動後に再作成します。
- 8種類のケーブルの4/16幅、独自テクスチャ74枚、既存モデル・レシピは変更していません。

単体の索引検査では、1,000独立区間/5,000ケーブルを用意し、1区間の切断に17作業単位、復旧に18作業単位を要しました。遠方の999区間を読み直さないことを検査しています。これは**実MinecraftサーバーでのTPS測定ではありません**。

導入前の各プロトコルの説明/検証記録にある「ディメンション単位の全体リセット」は、その版の制約です。この更新以降の無効化範囲は本書が正となります。
