# ボス施設・外壁修正・アフロディーテ報酬

対象: Minecraft 1.21.1 / NeoForge、作業ブランチ `feature/venus-hostile-mobs`。

## 追加する構造物

| 構造物 | ID | サイズ（幅×高さ×奥行き） | ボス | 必要な所持品 |
| --- | --- | --- | --- | --- |
| 金星将軍の城塞 | `venusmod:venus_general_fortress` | 41×20×59 | 金星将軍 | 金星核 |
| アフロディーテ神殿 | `venusmod:aphrodite_sanctum` | 49×24×57 | アフロディーテ・コア | 金星魂石 |

どちらも金星の荒野 `venusmod:venus_wastes` に自然生成する。既存の金星将軍の砦・アフロディーテ炉心施設は残し、対応する既存の構造物セット内で新旧の施設を同じ重みで選ぶ。配置候補の間隔・乱数saltは維持するため、構造物の種類を増やしてもボス施設の配置候補数は倍増しない。

| ボス施設のセット | 候補 | spacing / separation（チャンク） |
| --- | --- | --- |
| `venus_general_keep` | 既存の砦 / 新しい城塞（重み1ずつ） | 52 / 18 |
| `aphrodite_reactor` | 既存の炉心施設 / 新しい神殿（重み1ずつ） | 84 / 32 |

上記は配置候補を決める設定値で、一定距離ごとの生成を保証するものではない。

### 金星将軍の城塞

深層岩を基調とする四隅の塔付き城塞。入口階段、大門、左右の兵舎、中央通路、玉座の間から構成する。金星Mobスポナー4基と戦利品チェスト2個を配置し、最奥に金星将軍の祭壇を置く。祭壇の周囲はボスの出現と戦闘に必要な空間を確保する。

### 金星将軍の抜刀剣戦闘AI（2026-10-17改修）

- 金星将軍・抜刀剣持ちゾンビのコンボと高速斬撃は、攻撃対象が死亡・消失・別の対象へ変更された時、射線が遮られた時、追跡範囲（通常技は12ブロック、居合いは26ブロック）から外れた時点で中止する。中止後に残りの斬撃ダメージを出さない。
- 金星将軍だけはコンボ・高速斬撃・居合い中もパス探索でゆっくり前進する。速度倍率は通常追跡の **45%**。接近先は敵から約 **3.8ブロック** の地点とし、3.4ブロック以内で停止・4.4ブロック以上で再接近する（行動の揺れ防止）。
- 背後への定期テレポートは廃止。同じ攻撃者から有効なダメージを **8～15回（連撃ごとに抽選）**、各被弾間 **60tick（3秒）以内** に受けると攻撃者の背後への移動を試みる。攻撃者が変わるか間隔が3秒を超えた場合は新たな連撃として数える。失敗しても安全な場所が見つかるまで次の被弾時に再試行する。
- テレポート先には安全な床・空間が必要。移動元から着地点までのブロック衝突を、幅と高さを含む複数本のレイキャストで検証する。途中に壁や床があってすり抜けなければ移動できない場合、テレポートは実行しない。
- 既存の6連撃、平均+0.12秒の斬撃間隔、将軍の短いコンボ後クールタイム、SlashBladeのプレイヤーVMDモーションと描画時計は維持する。

### アフロディーテ神殿

クォーツ、黒石、金、水色のステンドグラスを使った大型神殿。前室には金星Mobスポナー2基、主神殿にはアフロディーテ祭壇と装飾用の照明・台座を配置する。入口から祭壇へ歩いて到達できる。

**旧式の回転入力機械や圧力コアを操作・破壊する必要はない。** 新規生成の神殿・炉心施設から旧式の制御装置と圧力コアを撤去し、照明や装飾に置き換えた。既存ワールドに残っている装置・コアは無視してよく、すでに壊していても攻略できる。

### アフロディーテの新しいシールド戦

- 体力: 1,500 HP。シールド耐久: **200**。
- アフロディーテ本体を通常攻撃すると青いボスバーのシールド耐久が減る。シールドが残っている間は本体HPへのダメージはない。
- **シールドを0にした攻撃の余剰ダメージは本体へ貫通しない。** 直後の攻撃から本体HPにダメージが入る。
- シールドが破壊されてから **200ゲームtick（10秒）** の間は攻撃が通り、経過するとシールドは満タン（200）で復活する。戦闘中は何度でも同じ周期を繰り返す。
- 青いバーはシールド残量、本体の赤いバーはHPと露出時間の残り秒数を示す。
- **Create・レッドストーン・制御装置・圧力コアは一切不要。** ボスは施設の有無に関わらず同じルールで戦える。
- シールド耐久と復活までの残り時間はセーブされ、サーバー再起動後も継続する。旧セーブの `ShieldUnlocked` 等の値は新仕様に影響しない。

### 召喚条件

既存のボス祭壇処理をそのまま利用する。金星将軍は金星核、アフロディーテは金星魂石を所持して祭壇付近へ近づくと出現する。キーアイテムは消費しない。出現に成功した祭壇は通常ブロックに変化し、その祭壇からの再召喚を防ぐ。ピースフルでは召喚しない。

## 既存構造物の外壁修正

奥の部屋で天井だけを高くしていたため、外周の壁や天井の段差に横長の隙間が残っていた。次の面を同じ壁材で埋める（アフロディーテ用の旧機械も新規生成では装飾へ変更）。

- 金星要塞: 奥の高い天井の手前にある段差面（58ブロック）。
- 金星将軍の砦: 奥の部屋の左右の壁上部と天井の段差面（59ブロック）。
- アフロディーテ炉心施設: 奥の部屋の左右の壁上部と天井の段差面（65ブロック）。

入口の階段、部屋の出入口、金星要塞のレバー式鉄扉は維持する。既存ワールドの建物やプレイヤー建築を自動で書き換える処理は追加しない。自然生成の変更と壁の修正は、更新後に新しく生成される構造物へ適用する。

## 王の財宝・王の宝物庫の入手

アフロディーテ・コアの通常の死亡ドロップに、次の独立した確定ドロップを追加する。

- 王の財宝 `venusmod:kings_treasure`: 1個。
- 王の宝物庫 `venusmod:king_treasury`: 1個。

既存の金星核・ヴェネサイトのドロップは維持する。両アイテムのクラフトレシピは登録しない。以前のビルドで生成されたレシピファイルも、生成前とリソース処理の最終出力から削除する。既に所持しているアイテムや、UUIDに紐づく宝物庫の内容は変更しない。

## 管理者向けの確認コマンド

探索:

```mcfunction
/execute in venusmod:venus run locate structure venusmod:venus_general_fortress
/execute in venusmod:venus run locate structure venusmod:aphrodite_sanctum
```

検証用ワールドの空いた場所へ配置:

```mcfunction
/place template venusmod:venus_general_fortress
/place template venusmod:aphrodite_sanctum
```

`/place template` は実行位置付近のブロックを書き換えるため、検証用の空き地で使用する。

## 生成・検査

新規構造物の生成器は `tools/java/BossStructureAssets.java`。既存のNBT書き出し処理を再利用し、`generateBossStructures` から `build/generated/bossStructures` へ出力する。通常の `processResources` が生成結果をJARへ含める。

`gradle check` では、新旧5施設の生成済みNBTを読み、床・天井・外壁・天井の段差・入口の保持を確認する。新しい2施設では、祭壇の一意性、出現空間、入口からの到達経路、宝箱・スポナー・アフロディーテの旧攻略装置の非生成も確認する。さらに自然生成の登録、両報酬の確定ドロップとレシピ非登録を検査する。

GameTestでは実際のテンプレート配置を4方向の回転で確認し、アフロディーテのシールド被ダメージ・10秒後の復活・セーブ互換性、死亡時の報酬とレシピ非登録を確認する。クライアントの最終描画・実プレイヤーによる戦闘バランスはこれらの自動検査とは別に確認する。

`gradle runServer -PvenusWorldgenSmoke=true` は検証用ワールドで金星の地形を生成し、自然生成の検索で新しい2施設を探す。生成済みピースの向きと位置から祭壇座標を求め、そのチャンクを完全生成して祭壇ブロックとブロックエンティティを確認する。すべて成功するとサーバーを終了する。この処理は専用プロパティ指定時のみ有効。

## 既存コードの互換修正

携帯生命維持装置の登録に使われていた `Item.Properties.enchantable(15)` は対象のMinecraft 1.21.1で利用できず、変更前のコードでもコンパイルを妨げていた。専用の `PortableLifeSupportItem` でNeoForgeの `getEnchantmentValue(ItemStack)` を実装し、エンチャント値15と耐久値600を維持する。

## 前回の検証記録（2026-10-17、旧シールド仕様）

Minecraft 1.21.1 / NeoForge 21.1.235 / Create 6.0.10、Java 21 / Gradle 9.2.1で確認した。

| 検証 | 結果 |
| --- | --- |
| `gradle build -PvenusTestCreate=true` | 成功。新旧5施設のNBT、自然生成の登録、報酬・レシピの検査を含む。 |
| 専用サーバーでの自然生成検証 | 成功。金星で新しい2施設を検索し、自然配置された祭壇とブロックエンティティを確認。 |
| Create導入状態の全GameTest | 41件中38件成功扱い（うち8件はSlashBlade未導入のため実連携検査をスキップ）、3件は既存失敗。新しい2施設×4方向の配置、登録、両報酬のドロップ、レシピ非登録は成功。 |
| 配布JARの内容 | 新旧5施設のNBTと更新済み死亡ドロップを収録。両アイテムのレシピを含まないことを確認。 |

GameTestの残る3件は、変更前のコミット `1e6ea2d` を別の作業ディレクトリへ展開し、上記のコンパイル互換修正だけを加えた環境でも同じ失敗を再現した。

- `componentsandserialization` / `extractioncapacityandblacklist`: 既存の収納ボックスが、可変の `ItemStack` を不変性が必要なData Componentとして保存する際のエラー。
- `phantasmreachesfurtherwithoutbreakingblocks`: 既存の幻想の爆風で、遠方の対象へのダメージを確認する検査の失敗。

これら3件は今回のボス構造物・入手経路の変更では修正していない。クライアント画面、実プレイヤーの戦闘バランス、SlashBlade本体を導入した連携動作は今回の検証対象外。
