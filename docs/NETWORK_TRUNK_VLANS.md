# トランクの許可VLANリスト

既存の802.1Q風トランクに、ポート単位の通過制限を追加します。ケーブル色の分離とは別の機能です。色が同じで物理的につながっていても、許可されていないVLANの通信は通しません。

## 設定例

```text
VLAN10/20の端末 ─ SW-A ═ Trunk ═ SW-B ─ VLAN10/20の端末
```

スイッチ間に配線したポートをTrunkにして、両端に許可リストを設定します。以下のP1は実際に配線した面に読み替えてください。

```text
port 1 mode trunk
port 1 allowed 10,20-30
ports
```

VLAN10と20〜30だけを通します。端末側Access VLANとIP設定は別途必要です。許可リストはVLANやIPアドレス・L3経路を自動生成しません。

```text
port 1 allowed all
port 1 allowed none
```

`all`は1〜4094を許可、`none`は全拒否です。既定値はallです。リストは置換方式で、追加/削除サブコマンドはありません。重複・順序・重なる範囲を正規化して保存します。入力は256文字以内、空欄は拒否します。`10,`や`30-20`、0/4095などを含む入力を部分的に受け付けません。

## GUIと同時編集

機器GUIのポート設定に「許可VLAN」欄を追加しました。Trunkでは編集可能、Accessでは灰色表示になり、保存された値は残ります。「適用」はそのページ全体を一括検証します。書きかけのリストを周期同期で消さず、同じポートのリストを他の人が編集していた場合は競合として拒否します。基本ページから許可リストを偽造しても適用しません。

同じ許可集合の再適用と、不正な入力の拒否では進行中の転送を消去しません。有効な通信条件の変更は従来の局所失効規則に従い、変更の影響がある物理網の転送・経路を再確立する場合があります。独立した別物理網は維持します。

## 送受信とNative VLAN

送信ポートと受信ポートの両方が、その側で分類されたVLANを許可する必要があります。片側だけで除外しても、そのVLANの往復通信は成立しません。タグなしのNative VLANも例外ではありません。

例: 初期Native VLANは1です。`allowed 10,20`ならタグ付き10/20は通せますが、Native 1の通信は通しません。Native通信も必要なら`allowed 1,10,20`とします。

両端のNative VLANが違う場合、この機能で自動修正しません。送信側は自身のNative VLANをタグなしで送り、受信側は自身のNative VLANに分類します。このため異なるNative VLAN間の意図しない接続を防ぐには、両端のVLAN設定も合わせてください。

Accessへ切り替えると、リストを保持したまま通過制限を無効にします。Accessは従来どおり自ポートのAccess VLANだけを扱います。Trunkに戻せば保存したリストが再び有効です。

許可VLANを減らしても、物理リンクの速度やLink Upは変えません。`ports`で許可リスト、ping/サービス操作でそのVLANからの通信結果を確認してください。IP ACLと機器の所有権も従来どおり別に適用されます。

## STPと保存

本MODのsimple/classic両STPも共通のVLAN通過規則を使います。除外されたVLANのポートはそのVLANの転送経路に含めず、classicでは再許可後も通常の状態遷移・待ち時間に従います。現実の全メーカーの管理フレーム例外や単一CST動作を完全再現する機能ではありません。

保存形式v14で各ポートの許可リストを保持します。旧v1〜v13はallとして移行し、以前の配線を更新だけで遮断しません。通常の機器ドロップ・再設置と設定バックアップ/復元にも含まれ、装着品・故障・所有権の保持は変わりません。更新前のバックアップを残してください。

フォーム通信の版をnetwork-3へ更新したため、サーバーとクライアントの両方を同じ新版へ更新してください。古いフォームで新しい許可リストを暗黙に上書きさせないためです。

## 負荷と範囲

許可文字列を解析するのは設定時だけです。不変のビット集合を使い、転送判定で文字列分割やVLANの全列挙をしません。既存の経路探索、VLAN数、STPインスタンス、GUI入力の処理・容量上限は維持しています。

136種のカラー/無染色ケーブル、4/16幅、画像・モデル・レシピ・専用タブは変更していません。GUI/JEIの既存VLANページに説明を追加しました。Q-in-Q、タグを重ねたフレーム、動的VLAN登録、VLAN別の複数L3サブインターフェースを追加したものではありません。
