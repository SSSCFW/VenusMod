## 失敗先行と純Java

旧実装で、共有1Gbpsの相手の一方が100Mbpsの場合に、もう一方の進捗が余り帯域を使えない失敗を再現しました。新しい配分API・優先度APIがなくコンパイルに失敗することと、新規ガイドが欠落して失敗することを確認してから実装しました。

| 新しい検査 | 成功数・内容 |
| --- | --- |
| BandwidthAllocatorTest | 20検査。容量・重み・複数ボトルネック、200個の決定的ランダム構成での上限/飽和/順序不変性 |
| TransferQosContractTest | 2検査。公開APIで100M+900Mの再配分と優先度CLI |
| TransferQosTest | 37検査。待機・完了・一括時間経過、変更/取消、他送信元の拒否、互換性 |
| TransferQosBoundaryTest | 18検査。NAT共有と失効、128転送の上限、計算キャッシュ、大きな時間経過 |
| TransferQosGuideTest | 18検査。構成図のアイコン、4手順、既存22トピック93手順の保持 |

新しい5クラス合計95検査、既存を含む96テストクラスをJava21で再コンパイル・実行し、すべて成功しました。アセット生成・参照検査は1,594 JSON・204 PNGで成功し、ガイドの23トピック97手順・231検査も成功しました。画像/モデル/レシピ生成器は無変更です。

ランダム構成のループ回数や128転送を、独立したプレイヤー数・TPS測定としては記載しません。既存ガイドの固定件数検査は新トピックだけを除き、元の件数と内容の検査を維持します。
